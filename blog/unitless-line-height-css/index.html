Unitless Line Height in CSS: Why Inheritance Matters

Choose readable line spacing and understand unitless inheritance. Compare number and length values, inspect nested text, and test user spacing overrides.

By Penta AIPublished 26 October 20263 min read

In this guide

  1. Compare two inheritance patterns
  2. Set typography roles deliberately
  3. Do not use line height as a button-sizing shortcut
  4. Allow user spacing changes
  5. Capture the decision in the type specification

A unitless line height is a multiplier applied to the element’s own font size. That makes it useful for text whose size changes across nested elements or responsive layouts. A computed length can instead be inherited as the same distance, creating cramped lines when a child uses larger text.

Begin with the reading task: a paragraph, heading and compact control do not need identical spacing. Establish a body-text baseline, then review other roles with their actual fonts and content. A single number is not a substitute for looking at several lines of real text.

Compare two inheritance patterns

.unitless-parent { font-size: 16px; line-height: 1.5; }
.length-parent { font-size: 16px; line-height: 24px; }
.large-child { font-size: 24px; }

If the child inherits the unitless value, its used line height is 36px. If it inherits the 24px length, that inherited distance remains 24px. This example isolates inheritance; other inline content and layout details can still influence a line box. MDN’s line-height reference explains the value types and their computed behavior.

Set typography roles deliberately

body { font-size: 1rem; line-height: 1.6; }
.article-title { line-height: 1.15; }
.field-label { line-height: 1.4; }
.article-copy { max-width: 65ch; }

These are starting values for review, not accessibility certification. A long reading column may need more comfortable spacing than a short display heading. Font metrics also matter: inspect ascenders, descenders, accents and punctuation using the actual loaded typeface.

Compare the same paragraph at a narrow and wide line measure. If it is difficult to follow across the page, consider the width as well as line height. Adding more space between lines cannot fully compensate for an unsuitable font size or an excessively wide reading column.

Do not use line height as a button-sizing shortcut

A control sized entirely by a large fixed line height may look centered with one short label and fail when the label wraps. Prefer explicit padding and an appropriate minimum size, then let text occupy the height it needs. Check the component with a longer translated label or a larger default font.

Likewise, separate paragraph spacing from line spacing. Margins or a parent layout gap control the distance between blocks; line height governs spacing within the text. Keeping these responsibilities distinct makes the spacing system easier to change without damaging reading rhythm.

Allow user spacing changes

WCAG’s text-spacing criterion concerns preserving content and functionality when users override spacing. It is not a command that every design must ship with all of the criterion’s test values. Avoid fixed-height text containers and clipping that cause information to disappear under those overrides.

Test larger line, word, letter and paragraph spacing together on a representative page. Inspect navigation, cards, form labels and error messages as well as body copy. A paragraph may adapt correctly while a compact card footer clips its final line.

Capture the decision in the type specification

Record font family, weight, size, line height and intended reading width as one role. Include a multi-line example instead of only an alphabet specimen. If the result differs between environments, use the rendered-font workflow before adjusting spacing around what might be a fallback font.
