Wrap Long URLs and Filenames with CSS overflow-wrap

Stop long strings from breaking cards while preserving readable text. Compare anywhere, break-word, nowrap and deliberate truncation with a filename example.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Build a filename row that can shrink
  2. Choose a text policy, not a global patch
  3. Review truncation as a product decision

A long filename, URL or identifier can overflow a component even when ordinary sentences fit. Use overflow-wrap when an otherwise unbreakable string needs an emergency line break. First make sure wrapping is allowed and the containing box can shrink; a text rule cannot repair every fixed-width layout constraint.

Build a filename row that can shrink

<div class="file-row">
  <span aria-hidden="true">↳</span>
  <span class="file-name">homepage-navigation-component-review-notes.txt</span>
</div>
.file-row { display: flex; gap: 0.5rem; max-width: 100%; }
.file-name {
  min-width: 0;
  white-space: normal;
  overflow-wrap: anywhere;
}

The filename stays complete in the document and can wrap inside the available row. The min-width rule addresses the flex item’s sizing constraint, while overflow-wrap addresses the string itself. Test the real component’s ancestors too: an explicit wide width farther up the tree can still make the page overflow.

MDN’s overflow-wrap reference distinguishes anywhere from break-word. Both can break a long string, but the new break opportunities affect min-content sizing for anywhere and not for break-word. That distinction can matter in intrinsic grid and flex sizing.

Choose a text policy, not a global patch

ContentStarting policy
Long filename or visible URLAllow wrapping with an emergency break.
Ordinary prosePreserve normal word boundaries.
Code where line structure mattersUse a contained scrolling code block.
Compact list with a detail viewConsider deliberate truncation with full text available.

Do not apply word-break:break-all to every paragraph just because one identifier is too long. It can split ordinary words aggressively and make reading harder. If you use hyphenation for prose, check the document language and the actual language-specific behavior; it is a different decision from wrapping an arbitrary URL.

If nothing wraps, inspect white-space on the element and its ancestors. A nowrap declaration can defeat the intended presentation. Then inspect the flex or grid item’s minimum size and the component’s explicit width. Keep these checks separate so you do not accumulate unrelated fixes.

Review truncation as a product decision

An ellipsis can be useful when users can easily open a full-detail view, but it may hide the exact part of a filename they need to distinguish. A hover-only title tooltip is not a dependable substitute for accessible full text on touch and keyboard devices. Decide where the complete value can be read and copied.

Test a short name, a long unbroken identifier, a URL with query parameters and text in another supported language. Copy the displayed value and confirm you did not insert literal spaces or hyphens into the data merely to influence layout. Save the chosen wrapping policy with the component so future content does not recreate the same overflow bug.
