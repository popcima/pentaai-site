Use datalist for Suggestions, Not a Restricted Choice List

Choose between datalist and select by whether custom input is allowed. Connect native suggestions to a labeled field and review accessibility fallbacks.

By Penta AIPublished 17 November 20262 min read

In this guide

  1. Connect the list without replacing the label
  2. Separate suggestions from validation
  3. Review the native popup on target devices

A text input connected to datalist can offer suggestions while still allowing other values. Use it when the suggestions help typing but do not define the only valid answers. If users must choose from an allowed set, a native select is often the clearer starting point.

Connect the list without replacing the label

<label for="workspace-tag">Workspace tag</label>
<input id="workspace-tag" name="tag" list="tag-suggestions"
       aria-describedby="tag-help">
<datalist id="tag-suggestions">
  <option value="Typography"></option>
  <option value="Color"></option>
  <option value="Layout"></option>
</datalist>
<p id="tag-help">Choose a suggestion or enter your own tag.</p>

The input’s list value references the datalist ID. Its name remains on the input because that is the form control. The help text explicitly permits a custom value, making the product rule visible instead of leaving the user to discover it through rejection.

Reference: MDN datalist element.

Separate suggestions from validation

Typing “Motion” into this example does not become invalid merely because Motion is absent from the suggestions. If the server maintains an allowed taxonomy, either validate against it with a clear error or use a selection interface that communicates the restriction. Do not treat the suggestion menu as a security boundary.

Option labels and displayed values can differ across browsers. Use simple values that make sense when typed, selected and submitted. Test duplicate and case-variant entries with the real server normalization rules, rather than silently changing a user’s label in the browser.

Review the native popup on target devices

A datalist popup is controlled by the browser and has styling and accessibility limitations. Review keyboard selection, screen-reader announcement, enlarged text and contrast on the combinations you support. Verify the ordinary text field remains usable if suggestions are unavailable; avoid putting indispensable instructions only in the popup.

  • Type a partial match, then choose a suggestion.
  • Enter a value absent from the list.
  • Clear the field and check required-field behavior if applicable.
  • Submit a long custom tag and inspect its display elsewhere.

For a short fixed set, compare this flow with a native select and grouped options. For a complex searchable picker, budget for a full keyboard and accessibility implementation rather than assuming a datalist can be styled into one.
