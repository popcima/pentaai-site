Register a Typed CSS Color Token with @property

Define a custom property’s color syntax, inheritance and initial value. Check registration failures and unsupported browsers before changing a shared token contract.

By Penta AIPublished 30 October 20261 min read

In this guide

  1. Declare a small color contract
  2. Distinguish invalid use from invalid registration
  3. Treat registration as a shared naming decision

@property registers a custom property with an expected syntax, an inheritance policy and an initial value. Use it when those rules are part of the component contract. A plain custom property and a registered one can behave differently, so registration deserves more review than simply adding another token name.

Declare a small color contract

@property --badge-accent {
  syntax: "<color>";
  inherits: false;
  initial-value: #174fa0;
}
.badge {
  --badge-accent: #174fa0;
  border: 2px solid var(--badge-accent, #174fa0);
}

The badge also declares a valid ordinary custom-property value as a baseline. The registration accepts colors and disables inheritance. A child using the registered property therefore does not automatically pick up an ancestor’s override. Choose true instead if inherited theming is the intended contract.

Reference: MDN: @property registration requirements.

Distinguish invalid use from invalid registration

For this color syntax, include all three descriptors. An invalid or incomplete registration can be ignored. Typed initial values must be computationally independent; the literal color above meets that requirement. Do not copy a relative length into another registration without checking its rules.

Create a local comparison with one badge using a valid color, one with an invalid candidate such as 12px, and one nested inside an overridden parent. Inspect each computed border color with registration enabled and disabled. Save that small specimen beside the component’s implementation notes.

Treat registration as a shared naming decision

  • Search the project for another registration using the same property name.
  • Verify whether nested badges should inherit a theme.
  • Test the baseline in a browser without the required support.
  • Keep invalid candidate values out of the production token source.

A useful review asks whether the extra contract solves a real problem: a constrained component API, interpolation requirement or predictable default. Do not register every variable merely to make a token file look more formal. Record the owner, accepted value category and inheritance decision so future overrides remain intentional.
