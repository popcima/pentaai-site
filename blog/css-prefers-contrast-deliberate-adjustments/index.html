Respond to a Contrast Preference with Specific UI Changes

Use prefers-contrast for deliberate border and text adjustments, test the ordinary state too, and keep this preference separate from forced-colors behavior.

By Penta AIPublished 24 November 20261 min read

In this guide

  1. Enhance a boundary without changing its geometry
  2. Do not equate more contrast with every alternate-color mode
  3. Review the full component set in each relevant state

Prefers-contrast reports a user preference for contrast, where supported. It does not measure whether a component already has sufficient contrast. Use it to make deliberate changes to a sound base design, such as strengthening a subtle field boundary.

Enhance a boundary without changing its geometry

.review-note {
  color: #303b34;
  background: #fff;
  border: 2px solid #8b978f;
  padding: 1rem;
}
@media (prefers-contrast: more) {
  .review-note { color: #101713; border-color: currentColor; }
}

The specimen keeps border thickness constant so changing the preference does not alter the box size. It strengthens the text and boundary colors. These example values still need assessment on the actual page; the media query itself is not a contrast test.

Reference: MDN CSS prefers contrast more.

Do not equate more contrast with every alternate-color mode

The preference can include no-preference, more, less or custom. A custom palette may not fit a simple higher-versus-lower contrast distinction. Forced-colors is a separate feature in which the browser can substitute system colors.

Inspect both features when supporting operating-system accessibility settings. Avoid broad filters that change every pixel or an assumption that a darker background always improves the user’s experience. Preserve meaningful borders, focus indicators and disabled-state distinctions.

Review the full component set in each relevant state

Compare the default and more-contrast modes with real content, including hover, focus and errors. Check whether formerly subtle separators become clear without overwhelming the information hierarchy. Confirm that the ordinary state remains readable when no preference is exposed.

Use browser emulation to inspect the CSS branch, then test the actual operating-system setting on supported platforms. Emulation verifies the condition and rendering; it does not establish that every platform maps its preferences the same way.

Review system color substitution separately. Measure real foreground and background combinations.
