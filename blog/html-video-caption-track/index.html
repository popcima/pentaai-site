Add a Caption Track to an HTML Video

Connect a WebVTT caption file to a video, verify timing and labels, and review native player controls. Distinguish captions from subtitles and transcripts.

By Penta AIPublished 30 October 20261 min read

In this guide

  1. Connect a labeled caption resource
  2. Write a small WebVTT specimen
  3. Watch with audio muted

A caption track can make spoken content and meaningful audio information available as synchronized text. For a native HTML video player, provide a WebVTT file through track. The markup connects the resource; accurate captions still require editing, timing review and a working player control.

Connect a labeled caption resource

<video controls preload="metadata" width="960" height="540">
  <source src="/media/review-demo.mp4" type="video/mp4">
  <track kind="captions" src="/media/review-demo.en.vtt"
         srclang="en" label="English" default>
</video>

These are example paths and dimensions for assets you must supply. Use the actual video dimensions. Captions include relevant speech and non-speech audio, while a subtitle track serves a different language-support purpose. Select the track kind based on its actual contents.

Reference: MDN: track element.

Write a small WebVTT specimen

WEBVTT

00:00:01.000 --> 00:00:03.500
Open the spacing panel.

00:00:04.000 --> 00:00:06.000
[Notification sound]

These cues are illustrative, not a transcript of an existing recording. Begin the real file with the WebVTT header, use valid cue times and serve it as text/vtt. Check its network response; a successful video request does not establish that the caption file loaded.

Watch with audio muted

  • Turn the track on and off using the player’s controls.
  • Verify cue timing, spelling, speaker changes and meaningful sounds.
  • Check that text remains readable on a narrow screen.
  • Navigate player controls with the keyboard and inspect their labels.

Host the track with an appropriate same-origin or correctly configured cross-origin setup. A console or network error is more useful evidence than repeatedly changing the label. Test the deployed page, because local files may not reproduce the production delivery rules.

Captions do not automatically explain meaningful visual actions that are never spoken. Review whether the recording also needs audio description or an equivalent explanation, and offer a transcript when useful for scanning. Keep the caption file version aligned with the video: editing the recording can invalidate every later cue even when the old file still loads.
