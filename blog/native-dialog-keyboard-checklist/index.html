Native HTML Dialog: A Keyboard and Focus Checklist

Build a small modal with the dialog element, showModal and an explicit close action. Check initial focus, Escape, background interaction and focus restoration.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Create a small information dialog
  2. Review the keyboard lifecycle
  3. Keep content usable at a narrow width

A native dialog opened with showModal provides modal behavior that a positioned div does not acquire from its appearance alone. Start with the native element, give it a clear name and explicit close control, then test the complete keyboard interaction. Styling the backdrop is only one part of a usable modal.

Create a small information dialog

<button type="button" id="open-help">Export help</button>
<dialog id="export-help" aria-labelledby="help-title">
  <h2 id="help-title">Export help</h2>
  <p>Your export includes the selected design notes.</p>
  <form method="dialog">
    <button autofocus>Close help</button>
  </form>
</dialog>
<script>
  const help = document.querySelector("#export-help");
  document.querySelector("#open-help").addEventListener("click", () => {
    help.showModal();
  });
</script>

Place the script after the markup or initialize it after the document is ready. The dialog form closes this informational dialog; it does not send a network request. Autofocus is reasonable for the close button in this tiny example. A larger dialog may need a different initial focus target based on what the user must read or do.

The MDN dialog reference distinguishes modal opening from merely setting the open attribute. With showModal, the dialog enters the top layer and the surrounding document becomes inert. Do not add tabindex to the dialog element itself.

Review the keyboard lifecycle

StepExpected observation
Open using Enter or SpaceThe dialog appears and focus moves inside.
Tab and Shift+TabBackground controls are not available while modal.
Press EscapeThe ordinary informational dialog closes.
Reopen and use Close helpThe explicit close action works.
After either close pathFocus returns to the invoking control when appropriate.

Test both closing routes because application event handlers can alter native behavior. Do not assume clicking the backdrop closes the dialog unless you have explicitly implemented and tested that behavior. The close button gives touch and keyboard users a clear route independent of backdrop behavior.

Keep content usable at a narrow width

dialog {
  box-sizing: border-box;
  width: min(32rem, calc(100% - 2rem));
  max-height: calc(100% - 2rem);
  overflow: auto;
  padding: 1.5rem;
}
dialog::backdrop { background: rgb(0 0 0 / 55%); }

Replace the short paragraph with realistic long content and enlarge the text. The close control must remain reachable. Avoid an unconditional display rule that makes a closed dialog visible; style its layout in a way that preserves the native closed state.

Finally, test the dialog with a screen reader and confirm its name is announced clearly. For a destructive action or a multi-step form, review initial focus, validation and cancellation as separate design decisions. This minimal help dialog demonstrates the lifecycle; it is not a complete interaction specification for every modal workflow.
