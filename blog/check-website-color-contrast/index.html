How to Check Website Color Contrast, State by State

Audit text, buttons and focus indicators against their real backgrounds. Learn contrast thresholds, inspect transparent colors and record actionable fixes.

By Penta AIPublished 26 October 20263 min read

In this guide

  1. Choose the requirement that fits the element
  2. Build a pair inventory
  3. Use a transparent-color example carefully
  4. Fix the role rather than one isolated pixel value
  5. Retest the states that are easy to miss

To check website color contrast, measure the foreground against the background that actually appears behind it, then repeat for relevant states and themes. A palette of individually attractive colors tells you very little about whether a specific label is readable. The unit of review is the color pair in context.

Start with a page containing body text, secondary labels, links, inputs and buttons. Keep the viewport and theme fixed for the first pass. You can use the same recording format on later pages instead of collecting disconnected screenshots.

Choose the requirement that fits the element

WCAG’s minimum text contrast criterion uses 4.5:1 for ordinary text and 3:1 for large text. Large text means at least 18pt, or 14pt bold; those correspond to 24 CSS px and approximately 18.67 CSS px. A large button does not make its small label “large text.”

The non-text contrast criterion addresses visual information needed to identify controls, states and meaningful graphics, generally at 3:1 against adjacent colors. It does not mean every decorative card border needs that ratio. Disabled controls and other exceptions require their own interpretation; avoid treating one number as a complete accessibility verdict.

Build a pair inventory

Pair to inspectContext to retain
Body text / page surfaceSize, weight and reading area
Secondary label / card surfaceActual background beneath the label
Button label / button fillDefault, hover and pressed states
Focus indicator / adjacent surfaceLight and dark surfaces where it appears
Input boundary / surrounding surfaceWhether the boundary identifies the field

Open an element’s color value in DevTools and inspect the available contrast information. Record the CSS colors and the result, not a value sampled from an antialiased edge of a letter. If the tool cannot determine the background, inspect ancestor surfaces, overlays and opacity rather than assuming white.

Use a transparent-color example carefully

Suppose a secondary label uses 50% black on a white surface. The visible result is around mid-gray, not solid black. The same declaration over a gray card produces another pair. This is why copying only the foreground declaration from a reference can produce a different accessibility outcome in your implementation.

As a simple opaque reference, black on white has a 21:1 ratio. The illustrative pair #4A4A52 on #FFFFFF is approximately 8.48:1. A tool may display rounded values; do not round a result upward to decide whether it reaches a threshold. These examples are calculations, not measurements of a particular customer’s site.

Fix the role rather than one isolated pixel value

:root {
  --surface-card: #ffffff;
  --text-primary: #17191c;
  --text-secondary: #4a4a52;
}
.card {
  background: var(--surface-card);
  color: var(--text-primary);
}
.card .caption { color: var(--text-secondary); }

Treat this as a starter pair, then evaluate every place that uses the role. Darkening a shared secondary-text token can improve several components, but a role that also appears on colored banners may need a separate inverse variant. Keep that reasoning in the palette inventory.

Retest the states that are easy to miss

Tab through controls and check focus, activate hover where it exists, inspect validation errors, and repeat in dark mode. Look at text over gradients and images at several positions. A passing static label says nothing about a focus ring that disappears against the next surface.

Finish with an actionable issue record: page, element, state, foreground, background, measured ratio and proposed correction. Contrast is one accessibility check among many; also test keyboard operation, meaningful labels and layout when text grows. This small record lets another person reproduce your finding without guessing which version of a button you meant.
