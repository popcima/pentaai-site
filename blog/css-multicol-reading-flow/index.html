Use CSS Columns for Flowing Text, Not Card Row Layout

Create readable multi-column text with a preferred column width and gap. Inspect the reading path, fragmentation and narrow-screen fallback before shipping.

By Penta AIPublished 17 November 20262 min read

In this guide

  1. Start with a preferred column width
  2. Review fragmentation as part of the content
  3. Follow the actual reading and keyboard path

CSS multi-column layout flows content down one column and then into the next. It is useful for some editorial and print layouts, but it is not a row-by-row card grid. Choose it only when that reading path matches the task and stays practical on the available screen.

Start with a preferred column width

.reference-copy {
  column-width: 20rem;
  column-gap: 2rem;
  column-rule: 1px solid #cdd6d0;
}
.reference-copy h2 { break-after: avoid; }
.reference-copy .short-note { break-inside: avoid; }

Fill the container with real headings and paragraphs. The column width is a preferred size used with the available space; it is not a promise that every column always measures exactly 20rem. Resize the parent and inspect the number and width of columns instead of forcing a fixed count at every viewport.

Reference: MDN multi-column layout concepts.

Review fragmentation as part of the content

A paragraph can continue in another column. Break-avoid requests help keep a short note or heading relationship together, but they are not an unlimited guarantee when the content cannot fit. Do not apply break-inside avoid to every large section and then expect the browser to balance arbitrarily long blocks perfectly.

Without a constrained height, a long article can produce tall columns that require readers to scroll down and then return upward for the next column. With a fixed height, content may produce additional columns that overflow horizontally. Test both the length of the document and the container’s height before deciding the pattern is appropriate.

Follow the actual reading and keyboard path

  • Read from the beginning of the first column to the next.
  • Tab through any links in the same content order.
  • Test headings near a column boundary and a long unbroken value.
  • Check enlarged text and a single-column narrow layout.

The DOM remains the content’s sequence; a visual arrangement that suggests reading across rows can conflict with it. Use grid or flexbox when items need that row-based relationship. For print, evaluate the columns in the print stylesheet separately, because page fragmentation adds another boundary. Keep an ordinary single-column view when it better supports reading.
