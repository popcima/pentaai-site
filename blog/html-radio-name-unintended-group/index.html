Fix Radio Choices That Deselect Another Component

Inspect radio names and form ownership when selecting one option clears an unrelated choice, and keep semantic fieldsets separate from grouping behavior.

By Penta AIPublished 21 November 20261 min read

In this guide

  1. Give independent decisions independent names
  2. Inspect the actual form owner
  3. Test selection and serialization together

If choosing a layout clears a theme choice, inspect the radio names. Two fieldsets do not create independent radio groups by themselves. Within the same form and tree, radios sharing a nonempty name belong to the same selection group.

Give independent decisions independent names

<form>
  <fieldset>
    <legend>Theme</legend>
    <label><input type="radio" name="theme" value="light" checked> Light</label>
    <label><input type="radio" name="theme" value="dark"> Dark</label>
  </fieldset>
  <fieldset>
    <legend>Layout</legend>
    <label><input type="radio" name="layout" value="wide" checked> Wide</label>
    <label><input type="radio" name="layout" value="compact"> Compact</label>
  </fieldset>
</form>

The legends explain the decisions, while theme and layout separate their selection behavior and submitted keys. Change both names to the same string in an isolated fixture to reproduce the coupling. Distinct IDs alone would not fix it; IDs identify controls for labels and references, not radio-group membership.

Reference: MDN radio.

Inspect the actual form owner

Separate forms can have independent radio groups using the same name. A form attribute can associate a radio with a form outside its visual wrapper, so inspect input.form rather than guessing from nearby borders. Radios without a form owner can still group with other matching radios in the same tree.

Repeated components inside one form often need an instance-specific group name. Preserve the server’s expected data structure when choosing those names. A visual duplicate should not accidentally become a single shared decision.

Test selection and serialization together

Select a theme, then a layout, and verify that both remain checked. Navigate each group with the keyboard and inspect the resulting FormData. Add a second component instance to expose naming collisions that one isolated component cannot show.

Use fieldset and legend for clear group context, and the form-owner guide when controls are rendered outside the form they submit.
