Find a Design Token Across Loaded Resources in Chrome

Search loaded resources for a custom property or class, then verify the winning declaration. Distinguish browser evidence from a complete repository search.

By Penta AIPublished 19 November 20262 min read

In this guide

  1. Search for an exact, distinctive string
  2. Connect the match to the rendered element
  3. Capture ownership rather than a list of matches

Chrome’s Search panel can locate a custom-property name or class across loaded resources. It is useful when you can inspect the deployed page but do not yet know which stylesheet owns a token. A text match is a lead, not proof that the declaration controls the selected element.

Search for an exact, distinctive string

  • Open DevTools, then More tools and Search.
  • Enter the full custom-property name, such as --surface-card.
  • Start with a literal search; enable regular expressions only when needed.
  • Open a result to inspect its surrounding source.

Keep punctuation in the query when it helps distinguish a declaration from ordinary copy. Case sensitivity matters for custom-property names. Searching only for a common hex value can return unrelated borders, backgrounds and examples that happen to share the same color.

Reference: Chrome Search panel.

Connect the match to the rendered element

Return to Elements and inspect the property that consumes the token. Trace its variable chain and the scope supplying each value. A token definition in an unloaded theme or inactive condition may be present in source without affecting the current component.

The Search panel searches loaded resources, not every file in the repository or every route that could load later. Network headers and responses have a separate Network search workflow. Generated bundles and source maps can also change which filenames and source text you see; record the deployed file when source mapping is unavailable.

Use variable fallback debugging for invalid values, and preserve observations in a design brief with clear source and scope information. This keeps a copied color from becoming an undocumented global rule.
