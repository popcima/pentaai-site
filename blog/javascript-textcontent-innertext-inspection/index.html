Choose DOM Text or Rendered Text for an Inspection

Compare textContent and innerText with hidden content and line breaks, avoid treating either as an accessible name, and write plain text without parsing markup.

By Penta AIPublished 23 November 20261 min read

In this guide

  1. Compare a visible label and a hidden note
  2. Name the representation in the review evidence
  3. Write plain text deliberately

TextContent reads a node’s text content without using its rendered layout. InnerText reflects rendered-text behavior, including relevant visibility and line breaks. Choose the representation that answers the inspection question instead of treating the two values as interchangeable.

Compare a visible label and a hidden note

<div id="specimen">Visible label<span hidden>Internal note</span><br>Second line</div>
<script>
const specimen = document.querySelector('#specimen');
console.log(specimen.textContent);
console.log(specimen.innerText);
</script>

For this rendered element, textContent includes the hidden note and does not turn the br element into a newline character by itself. InnerText excludes the hidden span and reflects the line break. Keep the specimen attached and visible; innerText on a non-rendered element can behave differently.

Reference: MDN textContent versus innerText.

Name the representation in the review evidence

A DOM-text inventory can be useful for checking source content, while a rendered-text comparison can help explain what is presented in a particular state. Neither is a substitute for the accessible-name calculation: labels, ARIA relationships and other semantics can change what assistive technology receives.

Reading innerText can require layout work. Avoid repeatedly reading it inside a large mutation loop when the task only needs source text. Collect the necessary evidence once under controlled styles and viewport conditions.

Write plain text deliberately

Use textContent when placing a plain string into a dedicated output node. It does not parse that string as HTML. Remember that assigning it replaces the node’s children, so do not apply it to a wrapper containing controls or markup that must survive.

Try text containing angle brackets, a hidden child and several lines. Document whether the expected result preserves DOM characters, rendered line breaks or an accessible label; otherwise two correct implementations can appear to disagree.

Inspect accessible names separately. Record the styles affecting presentation.
