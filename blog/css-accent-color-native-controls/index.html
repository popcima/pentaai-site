Style Native Checkboxes with CSS accent-color

Apply a brand tint to native form controls with accent-color. Preserve their behavior and review labels, focus, disabled states and browser differences.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Keep the input and label connected
  2. Know the scope of the property
  3. Review the full option row

If a checkbox only needs a different tint, try accent-color before rebuilding it from custom elements. Supporting browsers can apply the color while retaining the native control’s interaction. Treat the result as a browser-rendered control, not a promise of identical pixels on every platform.

Keep the input and label connected

<label class="export-option">
  <input type="checkbox" name="include-notes" checked>
  Include review notes
</label>
.export-option {
  display: flex;
  align-items: start;
  gap: .6rem;
}
.export-option input { accent-color: #245ec7; }
.export-option input:focus-visible {
  outline: 3px solid #174fa0;
  outline-offset: 3px;
}

The wrapping label connects the visible wording to the input and gives it a larger activation area. Keep the real input visible. This example changes its tint without using appearance: none, hiding it behind a pseudo-element or replacing the native checked state with a CSS class.

Reference: MDN: accent-color.

Know the scope of the property

The property applies to certain native controls and relevant states, such as checked checkboxes, radio buttons and portions of range or progress controls in supporting browsers. It is not a general way to recolor every part of every form element. An unsupported browser can retain its ordinary native appearance.

If the unchecked border does not match a mockup, that does not necessarily mean the declaration failed. Inspect the selected state and compare the browser’s control styling. Avoid layering increasingly broad selectors onto the page to chase a part the property does not control.

Review the full option row

  • Toggle with the keyboard and by clicking the label.
  • Check the focus ring on both light and dark surrounding surfaces.
  • Inspect checked, unchecked and disabled states.
  • Test long labels that wrap to two lines at a narrow width.

Use a real form when checking submission: the visual checkmark and the submitted value are related but separate concerns. Confirm the input has the intended name and value in the application. Do not imply that changing its tint changes how validation or form data works.

Review forced colors and supported operating systems as part of the component check. Native controls can adapt to user preferences, so avoid rejecting that adaptation simply because it differs from the brand screenshot. In the handoff, define the intended accent, label spacing and interaction requirements, while allowing platform-specific rendering where it remains clear and usable.
