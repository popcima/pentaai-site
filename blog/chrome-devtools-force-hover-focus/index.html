Inspect Hover and Focus Styles in Chrome DevTools

Freeze CSS interaction states in DevTools to inspect their styles. Separate a forced pseudo-class from real keyboard focus, pointer events and application behavior.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Freeze the styling you want to inspect
  2. Separate styling from behavior
  3. Finish with an unforced interaction pass

Forcing a pseudo-class in DevTools makes a CSS state easier to inspect without holding the pointer in place. It is useful for comparing a hover color or focus outline. It does not replace testing the real interaction, especially when JavaScript, keyboard order or touch behavior determines what appears.

Freeze the styling you want to inspect

  • Select the target element in the Elements panel.
  • In Styles, open the :hov state controls.
  • Enable the relevant state, such as :hover or :focus-visible.
  • Inspect the winning declarations and compare with the ordinary state.

Reference: Chrome DevTools: CSS features reference.

.sample-link { color: #174fa0; text-decoration: underline; }
.sample-link:hover { color: #102f65; }
.sample-link:focus-visible {
  outline: 3px solid currentColor;
  outline-offset: 3px;
}

This original link example makes hover and keyboard-focus styling independent. Toggle one state at a time, then inspect the combination. If the focus outline disappears when hover is active, check rule order and shorthand resets rather than assuming the browser cannot display both.

Separate styling from behavior

Forcing :hover does not necessarily execute the pointer event handlers that open a custom panel. Forcing :focus does not prove that the element can be reached in the page’s Tab sequence. If the application adds a class after an event, inspect that class-based state as well and reproduce the actual event path.

A parent’s :focus-within can change a whole field group while the input holds real focus. Select the relevant ancestor when investigating that relationship. Also check whether an overlay, disabled control or clipping container changes what the user can interact with, even when the CSS declarations look correct.

Finish with an unforced interaction pass

  • Clear the forced states so they cannot mask the real result.
  • Tab through the page and check focus order and visibility.
  • Use the pointer to enter, leave, press and release the control.
  • Try the interface without hover on a touch-capable device.

For a dropdown, verify opening, moving into the panel, activating an item and closing again. A beautiful frozen hover screenshot can hide a gap that makes the menu collapse as the pointer travels. Capture the trigger and path when reporting that bug.

In the handoff, label screenshots with the inspected state and say whether it was forced or reached through interaction. That distinction helps another developer reproduce the visual evidence and understand which behavior still needs testing.
