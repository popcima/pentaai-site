Count the Right Siblings with nth-child and nth-of-type

Debug structural selectors in mixed HTML. Compare sibling position, element type and filtered nth-child queries before using positional component styles.

By Penta AIPublished 17 November 20262 min read

In this guide

  1. Use a mixed sibling fixture
  2. Filter the counting set when that is the intent
  3. Avoid tying meaning to an accidental position

The difference between :nth-child() and :nth-of-type() is the set being counted. The first counts element siblings; the second counts siblings with the same element type. A class before either pseudo-class filters the match but does not automatically change that counting set.

Use a mixed sibling fixture

<section class="results">
  <h2>Saved samples</h2>
  <article class="card">First sample</article>
  <aside>Review note</aside>
  <article class="card">Second sample</article>
</section>
.results > .card:nth-child(2) { border-color: blue; }
.results > .card:nth-of-type(2) { background: #e7f3ec; }

The first rule matches the first article because it is the second element child. The second rule matches the second article because it is the second article sibling. Text nodes and whitespace do not increment these element positions. Inspect the matched elements instead of guessing from how many cards you see.

Reference: MDN nth-child.

Reference: MDN nth-of-type.

Filter the counting set when that is the intent

For the second sibling carrying a class, :nth-child(2 of .card) expresses a filtered counting set. Check target-browser support before depending on that selector. It differs from .card:nth-child(2), which asks whether the second element child happens to have the class.

Hiding an element with CSS does not remove it from structural counting. A hidden row can therefore disturb alternating stripes. Where supported, a filtered selector can explicitly exclude the hidden rows. A framework that removes the node entirely creates a different DOM, so test both visibility and rendering conditions.

Avoid tying meaning to an accidental position

  • Insert a heading or notice before the cards.
  • Hide one item, then remove it in a separate test.
  • Mix element types that share the same component class.
  • Check which selectors actually match in DevTools.

If the second card is special because it is “recommended,” give it an explicit state class or attribute. Use structural selectors for structure, such as alternating presentation, rather than encoding product meaning that breaks when content is reordered. For a matching rule that still loses, continue with the cascade debugging guide.
