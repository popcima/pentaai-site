meter vs progress: Represent a Value or a Task

Choose native meter or progress markup by meaning. Label the indicator, distinguish indeterminate work and keep visible values synchronized with actual state.

By Penta AIPublished 30 October 20261 min read

In this guide

  1. Show a measurement with context
  2. Show task completion separately
  3. Review labels, updates and outcomes

Use meter for a measured value within a known range, such as storage usage. Use progress for how much of a task has completed. Their bars may look similar, but the meaning differs. Choose the element from the information being communicated before styling its fill.

Show a measurement with context

<label for="storage">Sample storage usage: 6 of 10 GB</label>
<meter id="storage" min="0" max="10" value="6">6 of 10 GB</meter>

The values describe an illustrative measurement, not a running upload. Keep units in the visible label because the numeric attributes do not explain what the range measures. If you add low, high or optimum thresholds, define what those thresholds mean for the real product.

Reference: MDN: meter element.

Show task completion separately

<label for="upload">Example upload: 30%</label>
<progress id="upload" max="100" value="30">30%</progress>

For a task whose completion fraction is unknown, omit value to make progress indeterminate. Setting value to 0 represents a known zero-complete state, not unknown progress. Do not manufacture percentages merely to make an indicator feel active.

Reference: MDN: progress element.

Review labels, updates and outcomes

  • Check the accessible name and value for each indicator.
  • Keep the visible status text in sync with the attributes.
  • Test indeterminate, active, failed and completed task states.
  • Verify meaning remains understandable without the bar’s color.

A progress bar does not explain a failure or tell someone how to retry. Pair it with accurate task status and a recovery action where needed. If completion deserves an announcement, use a concise status update rather than announcing every percentage change as an urgent alert.

Inspect the native appearance in supported browsers before replacing it with complex custom visuals. A simple indicator with a clear label and accurate state is easier to verify than a decorative animation pretending to represent measured progress. Include the range, units, source of values and completion behavior in the component specification.
