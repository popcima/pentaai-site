Read Native CSS Nesting Without Miscounting Specificity

Use the nesting selector to distinguish component states from descendants. Check selector-list specificity and browser-parsed CSS when refactoring styles.

By Penta AIPublished 18 November 20261 min read

In this guide

  1. Separate component states from child selectors
  2. Inspect selector lists before refactoring
  3. Verify the CSS the browser receives

In native CSS nesting, & refers to the parent selector. It helps distinguish a state of the component itself from a descendant inside it. Read the resulting relationship before treating nested syntax as a shorter spelling of every preprocessor pattern.

Separate component states from child selectors

.sample-card {
  padding: 1rem;
  &.is-selected { border-color: #286b4a; }
  & .title { margin-block-start: 0; }
  &:focus-within { background: #edf6f0; }
}

The first nested rule targets a card that also has the selected class. The second targets a title inside a card. The third targets the card when focus is within it. Adding a space before the selected class would change the first relationship to a descendant match.

Reference: MDN native CSS nesting.

Inspect selector lists before refactoring

The nesting selector uses the highest specificity in its associated selector list, similar to :is(). Mixing an ID selector and a class selector in that list can therefore make a nested rule harder to override than a separately written class-only descendant rule.

#featured, .sample-card {
  & .title { color: #174fa0; }
}

Do not assume the class-matching branch contributes only class-level specificity here. Keep unrelated ID and class selectors separate when that stronger weight is accidental. Compare the winning rule before and after a refactor with a real component fixture.

Reference: MDN nesting specificity.

Verify the CSS the browser receives

  • Test selected and unselected cards.
  • Move focus between two controls inside the card.
  • Inspect a title inside a nested card instance.
  • Check whether a build tool rewrites the source before delivery.

Native nesting is parsed by the browser; a preprocessor can have different syntax and compilation rules. Avoid assuming a concatenation pattern such as a component suffix works identically. Use the cascade inspection workflow on the delivered stylesheet, and preserve the behavior rather than just the source indentation.
