Use bdi for Names Inside Mixed-Direction Text

Isolate dynamic names from surrounding punctuation with HTML bdi. Test Arabic, Hebrew, Latin text and numbers without changing the stored strings.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Isolate the unknown fragment
  2. Keep text isolation separate from layout and safety
  3. Test the boundaries that tend to move

Wrap an inline name of unknown direction in bdi when it sits inside a sentence, status row or activity feed. Bidirectional isolation keeps that inserted text from unexpectedly rearranging nearby punctuation and numbers. It addresses text ordering, which is separate from the layout direction of the whole interface.

Isolate the unknown fragment

<p dir="ltr">
  Reviewer: <bdi>سارة</bdi> — 3 notes
</p>
<p dir="ltr">
  Reviewer: <bdi>Alex</bdi> — 12 notes
</p>

These are illustrative names and counts. Keep the colon, separator and count outside the isolated name because they belong to the surrounding sentence. Without an explicit dir attribute, bdi behaves with automatic direction detection. If the inserted fragment is known to require a particular direction, specify that direction deliberately.

Reference: MDN bidirectional isolate element reference.

Keep text isolation separate from layout and safety

Setting text-align changes alignment, not the Unicode ordering algorithm. Likewise, switching margin-left to margin-inline-start supports a bidirectional layout but does not isolate a dynamic name. Use logical layout properties for geometry and bdi for the inline boundary.

When generating the example dynamically, assign the name with textContent or your framework’s normal escaped interpolation. bdi is not an HTML sanitizer. Do not inject an untrusted name through innerHTML just because it is wrapped in an isolation element.

Avoid reversing the stored characters to make one screenshot look correct. That can corrupt copying, searching and later display in another context. Keep the original string and let markup express the intended relationship to the surrounding text.

Test the boundaries that tend to move

  • Try a right-to-left name followed by a colon, dash or numeric count.
  • Try a Latin name inside a right-to-left page.
  • Include mixed-script names, parentheses and digits.
  • Copy the full line and confirm the underlying text remains sensible.
  • Check long names that wrap onto another line.

Save the exact failing string, page direction and surrounding punctuation in a bug report. “RTL text looks wrong” is difficult to reproduce; a small sentence with a clear expected reading order gives the reviewer a usable test. Ask a reader familiar with the language to review a real multilingual interface rather than judging correctness only from visual symmetry.
