Highlight a Field Group with :focus-within

Use focus-within for group context while keeping focus-visible on the actual control. Check nested fields, pointer focus and movement between groups.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Style context and control separately
  2. Do not confuse focus-within with focus-visible
  3. Follow focus across the boundary

Use :focus-within when a container should be highlighted while it or one of its descendants has focus. Keep the actual focused input or button visibly identifiable too. A group highlight gives context; it should not leave users guessing which control will receive their next keystroke.

Style context and control separately

<fieldset class="name-group">
  <legend>Reviewer name</legend>
  <label for="given">Given name</label>
  <input id="given" name="given">
  <label for="family">Family name</label>
  <input id="family" name="family">
</fieldset>
.name-group {
  border: 1px solid #a8b3c3;
  padding: 1rem;
}
.name-group:focus-within { background: #f1f6ff; }
.name-group input:focus-visible {
  outline: 3px solid #174fa0;
  outline-offset: 2px;
}

The background can stay highlighted as focus moves between these two fields. The outline follows the specific input. Native labels and the fieldset provide semantics independently of the CSS; the pseudo-class does not create an accessible group name.

Reference: MDN :focus-within reference.

Do not confuse focus-within with focus-visible

Focus-within responds to focus, including descendant focus in shadow trees. It is not restricted to the circumstances in which a browser chooses to show :focus-visible. Clicking an input may therefore highlight its group even when another control’s focus-visible treatment differs.

No tabindex is needed on the fieldset just to make the ancestor selector work. Adding a focus stop to every wrapper makes keyboard navigation longer without necessarily providing an action. Keep the normal focus path through the real controls.

Follow focus across the boundary

  • Tab from the preceding control into the first field.
  • Move between fields and check the individual focus indicator.
  • Tab out of the group and confirm its highlight clears.
  • Click a field, then repeat the sequence using Shift+Tab.
  • Check nested groups, error messages and forced-colors mode.

Avoid changing border width or padding on focus unless the space was already reserved. A moving field group can make the page feel unstable. An inset effect or background change can supply context without pushing adjacent content around.

If a group highlight appears stuck, inspect document.activeElement and whether a descendant still holds focus. Do not remove focus blindly to clear a visual style. For controls that need a shared question or label, use the fieldset and legend pattern first, then add the visual feedback.
