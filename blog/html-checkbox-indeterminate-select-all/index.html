Show Partial Selection with an Indeterminate Checkbox

Build a native select-all checkbox that reflects none, some or all choices. Derive the mixed state from the items and keep submission behavior separate.

By Penta AIPublished 17 November 20262 min read

In this guide

  1. Compute the summary from the items
  2. Keep appearance separate from submitted data
  3. Test transitions rather than a single screenshot

A select-all checkbox needs to distinguish a partial selection from both zero and complete selection. On a native checkbox, set the JavaScript indeterminate property for that mixed presentation. Derive it from the child choices so the summary cannot drift out of sync.

Compute the summary from the items

<label><input id="all-formats" type="checkbox"> All formats</label>
<fieldset id="formats">
  <legend>Export formats</legend>
  <label><input type="checkbox" name="format" value="svg"> SVG</label>
  <label><input type="checkbox" name="format" value="png"> PNG</label>
</fieldset>
const all = document.querySelector('#all-formats');
const items = [...document.querySelectorAll('#formats input')];
function sync() {
  const count = items.filter(item => item.checked).length;
  all.checked = items.length > 0 && count === items.length;
  all.indeterminate = count > 0 && count < items.length;
}
items.forEach(item => item.addEventListener('change', sync));
all.addEventListener('change', () => {
  items.forEach(item => { item.checked = all.checked; });
  sync();
});
sync();

The parent has no name because it summarizes the options rather than adding another export format. This minimal example assumes every child is enabled and the list is static. Recompute the collection when rows are added or removed; define whether disabled choices participate before extending it.

Reference: MDN indeterminate checkboxes.

Keep appearance separate from submitted data

Indeterminate is a property, not an HTML attribute you can make work by writing indeterminate="true". It does not create a third submitted value. The ordinary checked state still governs whether a named checkbox contributes data. Read the checkbox payload guide when wiring the selection to a form.

Test transitions rather than a single screenshot

  • Start with neither item selected: the summary is unchecked.
  • Select one item: the summary becomes mixed.
  • Select both: the summary becomes checked.
  • Activate the summary with Space and verify both child states.
  • Uncheck a child and confirm the mixed state returns.

Listen to the actual accessible state in a supported browser and screen reader. Keep native labels and fieldset semantics, and avoid replacing the checkbox with a drawn dash that has no input behavior. If the interface remembers a previous partial selection, document that additional interaction separately; this simple example only switches the whole set on or off.
