CSS Grid auto-fit vs auto-fill: What Happens to Empty Tracks?

Compare auto-fit and auto-fill with a sparse card grid. Understand empty tracks, minimum card widths and why the two values can look identical.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Compare the same three cards
  2. Avoid confusing an empty cell with an empty track
  3. Choose using a content scenario

Use auto-fit when a sparse set of cards should expand into available space. Use auto-fill when you want empty repeated tracks to remain part of the grid. The difference becomes visible when there is room for more columns than the content occupies; a full grid can make both declarations look the same.

Compare the same three cards

.card-grid {
  display: grid;
  gap: 1rem;
  grid-template-columns:
    repeat(auto-fit, minmax(min(100%, 15rem), 1fr));
}
/* Compare by changing only auto-fit to auto-fill. */

Start with three cards in a container wide enough for four minimum-width tracks. Keep the content and gap constant while switching the keyword. With auto-fit, empty repeated tracks collapse after placement. With auto-fill, those tracks remain. The 1fr maximum distributes free space across the tracks that remain.

Reference: MDN: repeat() and empty tracks.

Avoid confusing an empty cell with an empty track

A gap at the end of the last row does not necessarily represent an empty column. If earlier rows already occupy that column, the track is not empty. Test one card, three cards and enough cards for several rows. This separates the sparse-grid behavior from ordinary row wrapping.

The nested min() keeps the minimum from exceeding the available inline space when the container is narrower than 15rem. It does not make every kind of child content shrink: a fixed-width image or long unbroken value can still overflow. Inspect those children if the outer grid is correctly sized.

Choose using a content scenario

Imagine a saved-project screen with only one project. A card that expands across the full content area may feel oversized, even though auto-fit is behaving correctly. You could constrain the whole grid’s maximum width or choose auto-fill to retain the intended track structure. On a comparison strip with two equally important options, expansion may be exactly what you want.

  • Measure at the component’s actual width, not only the browser width.
  • Inspect the grid overlay to see track boundaries.
  • Check image crops and text wrapping after a card expands.
  • Verify that the one-item layout still has an obvious reading order.

Save screenshots with the item count and container width in the handoff. Those two facts explain the behavior more clearly than a screenshot of a fully populated grid alone.
