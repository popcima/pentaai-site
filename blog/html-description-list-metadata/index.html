Use a Description List for Named Metadata Values

Represent label-and-value metadata with dl, dt and dd before styling it as a grid. Preserve grouping, wrapping and reading order across narrow layouts.

By Penta AIPublished 19 November 20261 min read

In this guide

  1. Keep each name with its value
  2. Style the relationship without flattening it
  3. Review content variation and semantics

A description list is useful for groups of names and corresponding values, such as file metadata or a short specification. Start with dl, dt and dd when that relationship describes the content. A table is more appropriate when readers need to compare values across rows and columns.

Keep each name with its value

<dl class="asset-meta">
  <div><dt>Format</dt><dd>SVG</dd></div>
  <div><dt>Dimensions</dt><dd>1200 by 630</dd></div>
  <div><dt>Color role</dt><dd>Decorative illustration</dd></div>
</dl>

The values are an illustrative metadata record. Each div groups a term and its description inside the list. Keep a consistent valid grouping structure rather than placing arbitrary headings or controls between unrelated terms and values.

Reference: MDN description lists.

Style the relationship without flattening it

.asset-meta > div {
  display: grid;
  grid-template-columns: minmax(7rem, 1fr) minmax(0, 2fr);
  gap: .5rem 1rem;
  padding-block: .5rem;
}
.asset-meta dt { font-weight: 600; }
.asset-meta dd { margin: 0; overflow-wrap: anywhere; }
@media (max-width: 30rem) {
  .asset-meta > div { grid-template-columns: 1fr; }
}

The breakpoint and proportions are specimen values. Check the longest label and value in the real interface before adopting them. The source order remains name then value when the visual layout changes to one column, so the relationship does not depend on a desktop alignment trick.

Review content variation and semantics

  • Test an empty or unknown value with explicit product wording.
  • Include a long URL or filename and a translated label.
  • Check the reading sequence without CSS.
  • Review the structure in the supported accessibility environment.

Avoid using a description list merely to get convenient default indentation. Conversely, do not replace clear name/value relationships with disconnected spans just because the design resembles a card. If metadata becomes a comparison matrix, use real table header associations. Keep the content model clear first, then choose the layout behavior that presents it well.
