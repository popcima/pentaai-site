Fix a Decorative Overlay That Blocks Clicks

Inspect pointer hit testing when a visual overlay covers a control. Use pointer-events selectively and keep keyboard behavior and disabled semantics separate.

By Penta AIPublished 30 October 20261 min read

In this guide

  1. Keep decoration out of the pointer path
  2. Do not confuse click-through with disabled
  3. Verify the full interaction area

A transparent or decorative layer can sit above a button and receive the pointer event intended for the button. If the layer has no interaction of its own, pointer-events: none can let hit testing reach the content underneath. First confirm which element is covering the control.

Keep decoration out of the pointer path

<div class="preview-shell">
  <button type="button">Open preview</button>
  <div class="preview-glow" aria-hidden="true"></div>
</div>
.preview-shell { position: relative; }
.preview-glow {
  position: absolute; inset: 0;
  background: linear-gradient(120deg, transparent, #dceaff66);
  pointer-events: none;
}

The illustrative glow can overlap the button visually while the button remains the pointer target. Wire the real button action separately. aria-hidden describes the decoration’s lack of meaning; pointer-events controls hit testing. They solve different parts of the component.

Reference: MDN: pointer-events.

Do not confuse click-through with disabled

Applying pointer-events: none to an interactive element does not reliably disable it. It can still receive sequential keyboard focus. Native disabled controls, read-only values and inert regions have different semantics and should be chosen according to the task.

A child that restores pointer-events can become a target again. Events from a targetable descendant can also pass through its ancestors during propagation. If a parent handler still runs, inspect the event path rather than assuming the CSS prevents every event on that ancestor.

Verify the full interaction area

  • Click near the control’s label, border and corners.
  • Use the keyboard to focus and activate it.
  • Check touch interaction on the intended device.
  • Inspect overlays that appear only during loading or hover.

If the layer contains a real close button, tooltip action or other interactive content, do not make the entire component click-through without planning how those controls remain usable. A focused fix targets the purely decorative layer. Keep the overlay’s position, stacking order and pointer policy together in the component source so later visual edits do not quietly restore the obstruction.
