Treat Transition Completion as an Event, Not a Guaranteed Timer

Filter transitionend by target and property, account for cancellation and zero-duration states, and keep essential UI behavior independent of decoration.

By Penta AIPublished 24 November 20262 min read

In this guide

  1. Filter the transition you actually want to observe
  2. Account for states with no completion event
  3. Keep the logical state authoritative

Transitionend reports a completed CSS transition, but it is not guaranteed to fire after every style change. A transition may never start, may be canceled or may have zero effective duration. Avoid making essential cleanup depend only on one expected completion event.

Filter the transition you actually want to observe

const panel = document.querySelector('#transition-panel');
panel.addEventListener('transitionend', event => {
  if (event.target !== panel || event.propertyName !== 'opacity') return;
  console.log('Panel opacity transition completed');
});
panel.addEventListener('transitioncancel', event => {
  if (event.target !== panel || event.propertyName !== 'opacity') return;
  console.log('Panel opacity transition canceled');
});

Provide a panel with an opacity transition before using this diagnostic. The target check excludes bubbling events from descendants. The property check excludes other transitions on the same panel. The code records lifecycle events; it does not implement hiding, focus management or removal.

Reference: MDN transitionend propertyName cancellation.

Account for states with no completion event

Removing the transition or setting display:none before completion can prevent transitionend. A reduced-motion stylesheet may remove the duration entirely. A style assignment that does not change the computed value also does not create a transition just because a transition declaration exists.

Multiple transitioned properties can emit separate events. Using a generic once listener without filtering can consume an unrelated event and leave the intended action unhandled. Decide how cancellation and repeated toggles should affect the component state.

Keep the logical state authoritative

Test normal completion, rapid reversal, cancellation and reduced motion. Confirm the panel’s logical state, keyboard focus and visibility remain correct even when animation events are absent. Decoration should follow that state rather than become its only source of truth.

For code that truly must wait for motion, provide a completion strategy covering cancellation and the no-transition path. Record the exact property and element being observed so a later CSS refactor does not silently change the JavaScript contract.

Keep the transition property list intentional. Review the no-motion path.
