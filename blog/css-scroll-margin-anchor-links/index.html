Keep Anchor Headings Visible Below a Sticky Header

Fix headings hidden after anchor navigation with scroll margins or container padding. Test direct fragment URLs, changing header heights and keyboard navigation.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Apply an offset to the targets
  2. Identify the element that actually scrolls
  3. Separate scrolling from focus and motion

An anchor can scroll to the correct heading while a sticky header covers it. Reserve space for the target during scrolling instead of adding blank spacer elements to every section. Start by measuring the header in the state where the anchor lands, including any notice bar above it.

Apply an offset to the targets

<nav aria-label="On this page">
  <a href="#export-options">Export options</a>
</nav>
<h2 id="export-options">Export options</h2>
:root { --header-clearance: 5.5rem; }
.article h2[id], .article h3[id] {
  scroll-margin-top: var(--header-clearance);
}
@media (max-width: 40rem) {
  :root { --header-clearance: 7rem; }
}

Place the example heading inside the article container. The offsets are sample values; measure your own desktop and mobile header rather than copying them blindly. The margin affects scrolling alignment, not the ordinary gap between the heading and the preceding paragraph.

The MDN scroll-margin-top reference defines the target’s scroll-area outset. If the same clearance should apply broadly within one scrolling container, scroll-padding-top on that container is another design option. Avoid unintentionally applying both and creating a much larger gap.

Identify the element that actually scrolls

A documentation layout may scroll the page, a central content pane or a dialog body. Put the offset strategy on the relevant targets or scrolling container. Changing the root element will not necessarily solve an anchor inside a separately scrolling pane.

If the header height changes after loading, a fixed offset can become stale. Prefer a layout with predictable header dimensions where practical. If the application measures a dynamic header, update one shared clearance value and test it when banners appear or disappear. Do not scatter slightly different offsets across section stylesheets.

Separate scrolling from focus and motion

Scrolling a heading into view does not by itself complete a keyboard focus-management strategy. Test the next keyboard action after navigation, especially for a skip link or client-side route change. Keep the destination ID unique and stable so bookmarks remain meaningful.

If you enable smooth scrolling, provide an immediate-scrolling path for reduced-motion users. Review direct fragment navigation after fonts and images load as well: layout shifts can move a heading even when its initial offset was correct. The acceptance condition is a visible destination with a sensible continuation of navigation, not merely a changed hash in the address bar.
