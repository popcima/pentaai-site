Capture Website Screenshots with Reproducible Dimensions

Record viewport size, zoom and pixel ratio before comparing screenshots. Distinguish CSS layout dimensions from exported image pixels and capture real states.

By Penta AIPublished 16 November 20262 min read

In this guide

  1. Record the capture conditions
  2. Choose a capture that answers the question
  3. Make comparisons fair

A screenshot is easier to reproduce when it comes with its viewport, browser zoom, pixel ratio and interface state. Image pixel dimensions alone do not tell another developer how wide the page was in CSS pixels or which responsive layout produced it.

Record the capture conditions

({
  viewportWidth: window.innerWidth,
  viewportHeight: window.innerHeight,
  pixelRatio: window.devicePixelRatio,
  scrollY: window.scrollY
})

Run this read-only expression on the page being reviewed. Record browser version and zoom separately, along with the URL and the state that matters, such as an open menu or a loaded preview. A 1440-pixel-wide image could come from different layout and capture settings; inspect the exported file rather than guessing from its width.

Reference: MDN devicePixelRatio reference.

Choose a capture that answers the question

Use a viewport screenshot for a relationship involving the visible screen, such as a sticky header covering a button. Use a full-page capture for document flow, and a node capture for a small component. A tightly cropped card without its parent can hide the layout rule responsible for its width.

Chrome Device Mode can set an explicit responsive viewport and expose capture controls. Record any device emulation settings, and treat the result as a simulation rather than evidence that the page was tested on that physical device.

Reference: Chrome DevTools Device Mode guide.

Before capturing a long page, inspect lazy-loaded images and fonts. Scrolling can change loading and sticky states, so say whether the capture was made immediately after navigation or after scrolling. Do not silently combine different states into one supposed browser result.

Make comparisons fair

  • Use the same viewport and zoom for before-and-after images.
  • Wait for the intended font and relevant content to load.
  • Keep the same text, selected values and open panels.
  • Label forced DevTools states separately from real interaction states.
  • Remove unrelated overlays and avoid including private account data.

Attach the capture conditions to the image in the handoff. If a one-pixel discrepancy remains, inspect the actual CSS and rendered geometry instead of repeatedly resizing the screenshot. A useful comparison explains the mismatch and its environment, not only whether two images look different.
