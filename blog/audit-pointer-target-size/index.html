Measure the Clickable Target, Not Just the Icon

Review pointer target dimensions and spacing using WCAG 2.2 guidance. Inspect the real hit area, neighboring controls and exceptions in the interface context.

By Penta AIPublished 18 November 20262 min read

In this guide

  1. Separate the drawing from the hit area
  2. Apply the criterion in context
  3. Record a reproducible measurement

A small icon can sit inside a comfortably sized button, and a large visual decoration can still have a tiny click target. Measure the element that actually receives the pointer action. Start with a compact toolbar where neighboring controls are easy to activate accidentally.

Separate the drawing from the hit area

.icon-action {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  min-inline-size: 2.25rem;
  min-block-size: 2.25rem;
  padding: .5rem;
}
.icon-action svg { width: 1rem; height: 1rem; }

This specimen makes room around a small icon; the values are a design starting point. Use a native button with an accessible name, and check the computed size rather than assuming a rem value always equals a fixed number of CSS pixels. Test whether the padded area really activates the control.

Apply the criterion in context

WCAG 2.2 success criterion 2.5.8, at Level AA, sets a 24 by 24 CSS pixel target-size requirement with exceptions. These include specified spacing conditions, an equivalent conforming control, inline targets, unmodified user-agent controls and essential presentation. Read the exact exception before recording a pass.

For the spacing exception, the criterion uses a 24 CSS pixel diameter circle centered on each undersized target’s bounding box. Those circles must not intersect another target or the circle for another undersized target. It is not a blanket rule that every small icon merely needs a particular gap.

Reference: W3C understanding of target size minimum.

Record a reproducible measurement

  • Identify the hit-area element in DevTools.
  • Measure its bounding box in CSS pixels.
  • Inspect nearby targets and any overlap.
  • Record the exception relied on, if one applies.
  • Test the toolbar on a real touch device as well as with a mouse.

A minimum-size review is one check, not a complete accessibility verdict or a promise of comfortable use for every person. Larger practical targets may suit the task. Keep keyboard focus and control states in the same review so improving pointer activation does not hide the focused action or introduce overlapping buttons.
