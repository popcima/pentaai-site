CSS initial, inherit, unset and revert: Choose the Reset

Choose a CSS reset by the value you want to restore. Compare specification defaults, parent values and browser styles with a small reproducible example.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Use display to expose the difference
  2. Match the keyword to the source of the value
  3. Avoid resetting more than the repair requires

Choose initial for the property’s specification-defined initial value, inherit for the parent’s computed value, unset for the property’s natural inherited-or-initial behavior, and revert to roll back the current style origin. These keywords answer different questions; none means “undo my last edit.”

Use display to expose the difference

/* Compare these one at a time on an ordinary div. */
.example { display: initial; }
.example { display: revert; }

The initial value of display is inline. An ordinary div typically receives display: block from the browser stylesheet, so an author-level revert can restore that browser behavior while initial does not. The result depends on the element and applicable styles; do not treat revert as a universal block reset.

Reference: MDN revert keyword reference.

Match the keyword to the source of the value

.sample-parent { color: #174fa0; padding: 2rem; }
.sample-child {
  color: inherit;
  padding: unset;
}

In this fixture, the child receives the parent’s color. Padding is not naturally inherited, so unset resets it to its initial value rather than copying the parent’s 2rem. On a naturally inherited property such as color, unset instead behaves like inherit.

Try each keyword in an isolated rule and inspect the computed value. For revert in author CSS, look for the user or browser rule that becomes relevant after author-origin styling is rolled back. For inherited properties, values flowing from an ancestor can still matter. Revert does not simply choose an earlier declaration from the same author stylesheet.

Avoid resetting more than the repair requires

A broad all: unset or all: initial can remove useful visual defaults from controls, including the cues that distinguish an input or button. It does not remove their native HTML behavior, so the page can end up with controls that still work but no longer look interactive. Prefer resetting the specific property that is wrong.

  • State the intended result: parent value, initial value or browser styling.
  • Inspect the parent and browser rules before applying a reset.
  • Check keyboard focus and disabled states after changing a control.
  • Test the rule in a second component to expose accidental inheritance.
  • Review separate cascade-layer behavior if the actual goal is to roll back a layer.

Keep a before-and-after computed value in the issue report. That provides better evidence than saying a reset “fixed the CSS,” and it helps the next developer preserve the reason for the change.
