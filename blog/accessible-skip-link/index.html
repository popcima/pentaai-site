Build a Skip Link That Moves Keyboard Users to the Content

Add a visible-on-focus skip link and verify its target, focus behavior and placement above navigation. Test the full keyboard path on real page templates.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Connect the first link to main content
  2. Test the next Tab, not only the scroll
  3. Make the pattern survive template changes

A skip link lets a keyboard user bypass repeated navigation and reach the page’s main content. It should be early in the tab order, visible when focused and connected to a real destination. A link that merely changes the URL fragment while leaving the user trapped at the top does not complete that task.

Connect the first link to main content

<a class="skip-link" href="#main-content">Skip to content</a>
<header><!-- Repeated site navigation --></header>
<main id="main-content" tabindex="-1">
  <h1>Project guide</h1>
  <!-- Page-specific content -->
</main>
.skip-link {
  position: absolute;
  inset-block-start: 0.75rem;
  inset-inline-start: 0.75rem;
  padding: 0.75rem 1rem;
  background: white;
  color: #111;
  z-index: 10;
  transform: translateY(-200%);
}
.skip-link:focus { transform: none; }
#main-content { scroll-margin-block-start: 5rem; }

The negative tabindex allows the target to receive focus without adding a permanent extra stop to normal tab navigation. The layer number is only an example: place the link where its ancestor context can appear above your header. Do not use display:none for the unfocused state, because that removes the link from keyboard navigation.

W3C’s skip-link technique describes bypassing repeated material and moving focus beyond it. Keep the wording specific to the destination; “Skip to content” is easier to understand than an unexplained arrow icon.

Test the next Tab, not only the scroll

Reload a page and press Tab from the browser’s page area. Confirm the link appears with readable contrast. Activate it, then press Tab again and inspect where keyboard navigation resumes. It should continue in the main content rather than restarting through the navigation you intended to skip.

Run this sequence on a short page and a long page with a sticky header. Check that the main heading is not hidden behind the header after navigation. If your router intercepts fragment links, verify that it preserves destination and focus behavior. Add focused handling only if your actual application needs it, and test that handling with assistive technology.

Make the pattern survive template changes

Use a unique destination ID on every rendered page and keep it on the actual main region. Duplicate IDs can send navigation to the wrong place. When a page has several repeated regions, consider whether additional bypass links help, but avoid creating a new wall of links before the content.

  • The skip link is reachable before repeated navigation.
  • Its focused state is visible above the header.
  • Activation reaches the correct main region.
  • Subsequent keyboard navigation continues from that region.
  • The behavior survives zoom and a wrapped mobile header.

Include the keyboard sequence in template regression checks. A screenshot of the focused link proves only its appearance; the follow-up Tab test proves whether the shortcut actually saves the user work.
