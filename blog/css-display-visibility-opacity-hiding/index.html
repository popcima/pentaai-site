display, visibility or opacity: Choose How to Hide Content

Compare layout space, focus and accessibility exposure when hiding a component. Avoid invisible interactive controls and preserve a deliberate reveal path.

By Penta AIPublished 16 November 20262 min read

In this guide

  1. Compare one component in three states
  2. Inspect descendants and the intended semantics
  3. Specify the transition and focus destination

Choose a hiding method by the behavior you need, not only whether pixels disappear. Display: none removes the element’s layout box. Visibility: hidden generally preserves its space while hiding it. Opacity: 0 makes it transparent but can leave it interactive and exposed to assistive technology.

Compare one component in three states

.removed { display: none; }
.reserved { visibility: hidden; }
.transparent { opacity: 0; }

Apply each class separately to a local fixture containing a card and a native button. Watch the next card’s position, then navigate with Tab. The transparent version can still receive focus and pointer interaction. An invisible button that accepts input is usually an incomplete state transition.

Inspect descendants and the intended semantics

Visibility is inherited, and descendants can explicitly become visible, so inspect nested overrides if a hidden container still shows content. Display: none on an ancestor removes the subtree from rendering. Ordinary accessibility exposure also differs from opacity-based transparency; verify the actual accessibility tree.

Do not substitute these rules for a visually-hidden text helper that supplies an accessible name. Conversely, do not use a clipped-text helper to conceal a whole interactive panel while leaving its controls in the keyboard path. Naming a compact control and deactivating a panel are different tasks.

Inert can be relevant when a subtree must remain visually present but inactive. It has its own behavior and should be chosen intentionally. Pointer-events: none alone does not remove a control from keyboard navigation, so it is not a complete repair for a transparent panel.

Specify the transition and focus destination

  • Check whether the layout should collapse or reserve space.
  • Tab forward and backward through the hidden state.
  • Inspect accessibility exposure for the container and descendants.
  • If hiding content that contains focus, move focus to a useful visible location.
  • Reveal the component again and verify its content and state are preserved as intended.

If a fade is part of the transition, distinguish the temporary animation from the final hidden or inactive state. Keep the component usable when motion is disabled or canceled. Use the inert-panel workflow when the task is deactivation, and the visually-hidden text pattern only for its narrower purpose.
