Choose a Font Display Policy from the Loading Experience

Compare swap, fallback and optional in a controlled font-loading review. Test readable fallback text and layout changes without promising exact timing across browsers.

By Penta AIPublished 19 November 20262 min read

In this guide

  1. Set the policy on the font face
  2. Compare the practical tradeoffs
  3. Review cold and repeat visits

Font-display is an @font-face descriptor that controls how a font face is used while it becomes available. Choose it from the reading experience during loading, not only from the final branded screenshot. A useful comparison includes the fallback face and the layout change when a web font arrives.

Set the policy on the font face

@font-face {
  font-family: "Review Sans";
  src: url("/fonts/review-sans.woff2") format("woff2");
  font-style: normal;
  font-weight: 400;
  font-display: swap;
}
.article-copy { font-family: "Review Sans", system-ui, sans-serif; }

Use a real licensed file and correct descriptors in place of the specimen. Putting font-display on the article element does not configure the face. Keep the font, content and network conditions the same while comparing policies.

Reference: MDN font-display periods.

Compare the practical tradeoffs

Swap uses an extremely small block period and permits a later swap. Fallback uses an extremely small block period with a limited swap period. Optional has an extremely small block period and no swap period, so the web font may not replace the fallback during that view. Browser timing and decisions are not universal fixed deadlines.

The visual cost depends on the fallback’s metrics. A heading that gains a line or a button that grows after a swap can disturb the task even when the font file is relatively small. Measure the actual component, and do not claim that optional guarantees the font is never downloaded or that swap prevents every loading problem.

Review cold and repeat visits

  • Compare readable text before the custom face is ready.
  • Inspect wrapping and component dimensions after loading.
  • Repeat with a cached font under otherwise comparable conditions.
  • Test a failed request and a slow connection without hiding content indefinitely.

Use fallback-size review to investigate metric differences and measured font preloading only when early discovery is a real problem. Record the chosen policy, fallback and observed tradeoff so a later typography change does not silently invalidate the loading decision.
