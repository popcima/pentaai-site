Z-Index Not Working? Trace the Stacking Context

Debug a menu hidden behind another component. Trace ancestor stacking contexts, distinguish clipping from layering and repair the relevant stacking boundary.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Reproduce the conflict with two siblings
  2. Inspect both ancestor chains
  3. Choose a repair with a clear owner

A larger z-index does not guarantee that a dropdown will appear above the whole page. It orders the element within its stacking context. If that context sits below a neighboring component, the dropdown cannot escape simply by changing 20 to 999999. Find the boundary that separates the overlapping elements before choosing a new number.

Reproduce the conflict with two siblings

<header class="site-header">
  <div class="menu-panel">Menu content</div>
</header>
<main class="page">Page content</main>
.site-header { position: relative; z-index: 1; }
.menu-panel { position: absolute; z-index: 100; }
.page { position: relative; z-index: 2; }

Where these boxes overlap, the page’s context is above the header’s context. The menu’s 100 is local to the header. Raising the header to 3 changes the relevant comparison; raising only the menu does not. The numbers in this example are illustrative layer assignments, not a universal scale for every application.

MDN’s stacking context guide lists context creators, including certain positioned elements, transforms and opacity below 1. A transform added for animation can therefore change layering even when no new z-index appears beside it.

Inspect both ancestor chains

Select the hidden panel, then its ancestors, and record which ones establish contexts. Repeat for the element covering it. Find the first level where the two chains can be compared. This is more reliable than searching only the panel’s component stylesheet, because the decisive property may belong to a layout wrapper.

EvidenceUseful next step
Panel is behind a siblingCompare their ancestor contexts.
Panel is cut off at an exact edgeInspect overflow and clipping on ancestors.
Panel looks translucentCheck opacity and overlays before changing layer order.
Problem begins during animationInspect transforms and animated ancestor properties.

Temporarily disabling a suspected property in DevTools is a diagnostic step. If removing a transform fixes the menu, check why that transform exists before deleting it from source. The component may still need its animation or positioning behavior.

Choose a repair with a clear owner

For a header-owned dropdown, a deliberate header layer may be enough. For an overlay shared across unrelated sections, a dedicated overlay location can simplify the hierarchy. Moving markup also changes inheritance, positioning and event assumptions, so review those alongside the visual fix. Native modal dialogs use the top layer; treat that as a different mechanism, not another huge z-index value.

Create a small layer inventory for the page: ordinary content, navigation, floating controls and modal UI. Test the repaired menu near a sticky sidebar and at a narrow viewport. Then close it and confirm that it no longer intercepts clicks. A completed layering fix should explain which context changed and why, rather than leaving a collection of escalating numbers behind.
