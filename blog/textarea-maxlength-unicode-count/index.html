Why a Textarea Character Counter Disagrees with maxlength

Compare UTF-16 limits with user-perceived characters before building a counter. Test emoji, accents and pasted text, then align browser and server rules.

By Penta AIPublished 16 November 20262 min read

In this guide

  1. Define what the limit actually counts
  2. Align the counter, control and submission rule
  3. Use a small multilingual test set

A textarea’s maxlength is measured in UTF-16 code units, which are not always the same as visible characters. A counter based on JavaScript string length follows code units too. Emoji and combining sequences can expose a mismatch between that technical limit and a product promise such as “200 characters.”

Define what the limit actually counts

const sample = "A\u{1F600}";
console.log(sample.length); // 3 UTF-16 code units
const segments = new Intl.Segmenter("en", {
  granularity: "grapheme"
});
console.log([...segments.segment(sample)].length); // 2 graphemes

The example uses an escaped emoji so the underlying string is unambiguous. A grapheme approximates a user-perceived character more closely than a code unit. It is still a deliberate counting policy that needs agreement across client and server.

Align the counter, control and submission rule

If the product intentionally uses the native code-unit limit, make the counter use the same basis and explain surprising behavior clearly. If the product requires a grapheme limit, do not combine it with the same numeric maxlength and assume they enforce equivalent rules. Design the validation and server implementation around the chosen policy.

A byte limit for storage or network payload is another measure. Do not label it as a character limit without a conversion policy. Also consider pasted line breaks and normalized text: transformations performed after entry can change the count being validated.

Keep the current count visible without making a screen reader announce every keystroke. Announce a meaningful threshold or validation result only when that helps the task. Preserve text when reporting an over-limit value rather than silently deleting content the user has composed.

Use a small multilingual test set

  • Plain ASCII text exactly at the limit.
  • An emoji represented by a surrogate pair.
  • A combining accent and a precomposed accented letter.
  • A multi-code-point emoji sequence.
  • Pasted multiline text and an existing saved value.

Check the count during entry, after application restoration and on the server response. Record the counting unit in the component specification, even if the interface uses friendlier wording. The error-message workflow should explain how to recover without pretending that every visible symbol has the same storage representation.
