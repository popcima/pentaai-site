Read Every Selected Value from a Multiple Select

Use FormData.getAll for repeated field names, inspect empty selections, and keep the native multiple-select interaction understandable on different devices.

By Penta AIPublished 20 November 20261 min read

In this guide

  1. Preserve the repeated name
  2. Define what an empty selection means
  3. Check selection and serialization together

A multiple select can submit several entries with the same field name. FormData.get returns just one value; getAll returns the collection. Converting the whole form directly into a plain object can silently discard repeated entries.

Preserve the repeated name

<form id="filters">
  <label for="topics">Topics (choose one or more)</label>
  <select id="topics" name="topic" multiple size="3" required>
    <option value="css" selected>CSS</option>
    <option value="type" selected>Typography</option>
    <option value="color">Color</option>
  </select>
</form>
<script>
const data = new FormData(document.querySelector('#filters'));
console.log(data.getAll('topic')); // ['css', 'type']
</script>

The selected attributes establish this specimen’s initial choices. Read a fresh FormData after a later user change; the original object is a snapshot, not a live view of the form. Keep array handling on the receiving side too so the second choice does not disappear after transport.

Reference: MDN select.

Define what an empty selection means

Without selected options, the field contributes no selected values and getAll returns an empty array. Required can prevent ordinary valid submission with no choice, but constructing FormData does not itself run the form’s validation workflow. A script that submits data must preserve the intended checks.

Native multiple-selection gestures vary across devices and platforms. For a short visible set of independent filters, labeled checkboxes may be easier to discover. Choose based on the interaction, not only on the space a compact list saves.

Check selection and serialization together

Select two options, deselect everything, and choose the final option alone. Inspect the array after each change and test the actual submitted request. Include keyboard use and a touch device in the review. Confirm the selected styling stays readable in forced colors rather than relying on a custom color alone.

Use optgroup for meaningful groups and compare checkbox submission rules when evaluating another control.
