Understand CSS Animation Fill Modes Before and After Playback

Diagnose jumps during animation delay and after completion. Compare forwards, backwards and both without mistaking a retained animation value for permanent state.

By Penta AIPublished 16 November 20262 min read

In this guide

  1. Make the resting state explicit
  2. Compare the fill modes against the timeline
  3. Review the boundaries, including cancellation

Animation-fill-mode controls whether animation values apply before playback begins and after it finishes. It does not change the animation’s duration or make its last frame a permanent application state. Inspect the base rule, keyframes, delay and direction together when an element jumps unexpectedly.

Make the resting state explicit

.notice {
  opacity: 1;
  transform: none;
  animation: notice-enter 240ms ease 120ms backwards;
}
@keyframes notice-enter {
  from { opacity: 0; transform: translateY(.5rem); }
  to { opacity: 1; transform: none; }
}
@media (prefers-reduced-motion: reduce) {
  .notice { animation: none; }
}

This original entrance example uses backwards so the initial animation values can apply during the delay. The ordinary rule already describes the final visible state. If animation is disabled for reduced motion, the notice remains visible rather than relying on an animation to reveal essential content.

Reference: MDN animation-fill-mode reference.

Compare the fill modes against the timeline

None leaves animation values out of the periods before and after playback. Backwards can apply the relevant starting keyframe during the delay. Forwards retains the relevant ending values after completion, and both combines those behaviors. Direction and iteration settings determine which keyframe is relevant, so “forwards means the 100% rule” is not a universal shortcut.

A forwards-filled animation can continue to override an ordinary declaration. If changing a class appears to have no effect after playback, inspect active animation styles and remove the animation temporarily. The retained result is part of the animation’s styling behavior, not a rewrite of your stylesheet.

Review the boundaries, including cancellation

  • Inspect the element before the delay ends.
  • Pause midway and inspect the properties being animated.
  • Check the state immediately after completion.
  • Remove the animation class and verify the base state is usable.
  • Test reverse or repeated playback if the component supports it.

Avoid using an ending opacity of zero as the whole implementation of hiding an interactive panel. Focus and accessibility exposure need an intentional state change. Use the animation timing workflow to inspect the timeline, then document which values belong to the component and which exist only during motion.
