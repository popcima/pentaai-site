Fix a Number Field That Rejects an In-Range Decimal

Debug stepMismatch separately from minimum and maximum errors. Choose a numeric step and base that match the permitted increments, then explain them clearly.

By Penta AIPublished 18 November 20261 min read

In this guide

  1. Define a deliberate sequence
  2. Inspect the specific failure
  3. Separate quantities from identifiers

A number can be between min and max yet still fail a number field’s step constraint. The accepted values follow increments from a step base; they are not simply every number inside the range. Inspect validity.stepMismatch before changing unrelated range limits.

Define a deliberate sequence

<label for="spacing">Spacing increment</label>
<input id="spacing" name="spacing" type="number"
       min="0.5" max="4.5" step="0.5"
       aria-describedby="spacing-help">
<p id="spacing-help">Use 0.5 to 4.5, in increments of 0.5.</p>

In this example, 0.5, 1 and 1.5 fit the sequence; 0.75 does not. The minimum supplies the step base here. Without an applicable minimum, the value attribute can provide a base; otherwise number inputs generally use zero. An omitted step defaults to 1, which can surprise a design that visibly invites decimals.

Reference: MDN number input constraints.

Inspect the specific failure

const input = document.querySelector('#spacing');
console.table({
  value: input.value,
  stepMismatch: input.validity.stepMismatch,
  underflow: input.validity.rangeUnderflow,
  overflow: input.validity.rangeOverflow
});

Test one allowed value, one off-step value and values just outside each boundary. Keep the numeric model consistent on the server. Floating-point arithmetic and unit conversions need deliberate handling; a browser accepting the input does not prove downstream calculations preserve the intended precision.

Use step="any" when arbitrary numeric increments are permitted. It removes the step restriction, not the minimum, maximum or other validation rules. Do not set any just to silence an error if the product actually accepts half-unit increments only.

Separate quantities from identifiers

  • Try typing and pasting a decimal rather than only using spinner buttons.
  • Check the field in the supported locale and browser combinations.
  • Keep the allowed increment visible before validation fails.
  • Retain a correction path without silently rounding meaningful values.

For a postal code or an identifier with leading zeros, reconsider number input entirely. The inputmode comparison explains how to request a numeric keyboard while retaining a text value when arithmetic is not the task.
