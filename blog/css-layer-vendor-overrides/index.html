Put Vendor CSS in a Layer Before Writing Overrides

Control vendor styles with explicit cascade layers. Check unlayered rules and reversed important precedence before trying to win with stronger selectors.

By Penta AIPublished 19 November 20261 min read

In this guide

  1. Establish the order before the rules
  2. Account for unlayered and important rules
  3. Test the contract with a small fixture

Cascade layers let you establish precedence between groups of author styles before comparing selector specificity within those groups. They are useful when vendor CSS is deliberately placed in an earlier layer and application overrides live later. The vendor stylesheet must actually belong to a layer for that plan to work.

Establish the order before the rules

@layer vendor, components, overrides;
@import url("/styles/vendor.css") layer(vendor);

@layer overrides {
  .sample-button { background-color: #286b4a; }
}

Replace the illustrative URL with the stylesheet your project uses. Keep import placement valid: a layer-order statement can precede the import, but ordinary style rules should not. Inspect the delivered CSS if a bundler rewrites imports; the source file’s appearance does not prove the browser received the same layer structure.

Reference: MDN import layers.

Account for unlayered and important rules

Within the author origin, normal unlayered declarations outrank normal declarations in named layers. Moving only your override into a layer while leaving vendor rules unlayered can therefore weaken the override. Check the layer shown for the actual winning declaration.

Important declarations reverse layer precedence: earlier layers outrank later ones, and layered important declarations outrank unlayered important declarations. Do not extend the normal “later wins” rule to an important conflict. Treat an important vendor rule as a separate issue rather than escalating every application selector.

Reference: MDN layer precedence.

Test the contract with a small fixture

  • Compare a vendor rule and an override targeting the same property.
  • Add an unlayered normal rule and observe the change.
  • Test an important conflict separately.
  • Verify hover, focus and disabled variants still have their intended appearance.

Avoid reorganizing the entire stylesheet to fix one unexplained declaration. First use the cascade debugging workflow to identify origin, importance, layer and specificity. Document the layer order once so future components follow the same override contract instead of creating new local exceptions.
