Route Submit Buttons with Native Form Overrides

Use formaction and formmethod for distinct native submission destinations, then verify validation, keyboard submission and any JavaScript interception.

By Penta AIPublished 20 November 20261 min read

In this guide

  1. Make each action explicit
  2. Keep native transport and custom handlers aligned
  3. Test each trigger independently

A submit button can override its form’s destination and method. This supports a normal submit path and a separate preview path without changing the form action on every click. The server still needs to implement both destinations.

Make each action explicit

<form action="/reviews/save" method="post">
  <label for="review-title">Review title</label>
  <input id="review-title" name="title" required>
  <button type="submit">Save review</button>
  <button type="submit" formaction="/reviews/preview" formmethod="post">
    Preview review
  </button>
</form>

These are illustrative endpoint paths, not services provided by the example. The save button uses the form settings; the preview button supplies overrides. Both still participate in normal validation because neither has formnovalidate. Preview should not bypass required checks accidentally just because it is a secondary action.

Reference: MDN button.

Keep native transport and custom handlers aligned

If a script cancels submission and calls fetch with a hard-coded URL, the browser’s native routing no longer supplies the complete behavior. Read the submitter deliberately and reproduce only the intended transport policy. Also decide whether preview is truly a server submission or a local display action that should use type="button".

Do not send sensitive form contents with GET merely for convenient preview routing: GET places submitted fields in a URL. Keep server-side validation and authorization appropriate to each operation.

Test each trigger independently

Activate Save, activate Preview, and press Enter from the text field. Confirm which button or default path the browser uses and inspect the request destination and method in Network. Repeat with an empty required field. If a script triggers submission, requestSubmit with the chosen button can preserve its role in native submission.

See SubmitEvent.submitter for identifying the action and requestSubmit versus submit for programmatic behavior.
