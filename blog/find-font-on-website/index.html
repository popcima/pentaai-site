How to Find the Font on a Website in Chrome

Identify a website’s real rendered font, size, weight, and line height in Chrome. Learn why font stacks and screenshot guesses can mislead you.

By Penta AIPublished 25 October 20264 min read

In this guide

  1. Choose a method for the text you have
  2. Inspect the exact text element
  3. Why the first font name may be wrong
  4. Record a useful typography specimen
  5. Troubleshoot a font that still looks different
  6. Turn the observation into your own type system

To find the font on a website, right-click the text, choose Inspect, and open Elements → Computed in Chrome DevTools. Check font-family, then scroll to Rendered Fonts to identify the typeface actually used. Record the size, weight, and line height too: the family name alone will not reproduce the typography.

This guide is for live, selectable website text. If the lettering is inside a photograph, screenshot, or outlined logo, you need image-based identification instead. Start by checking which kind of material you have.

Choose a method for the text you have

What you can accessStart hereWhat to verify
Selectable live textChrome’s element inspectorRendered font and computed styles
A screenshot or photoAn image-based font matching serviceCandidate matches, not an exact CSS declaration
A logo built with SVG pathsBrand guidelines or the original design fileWhether the lettering was customized
Your own source projectFont declarations and component stylesWhich files load in the browser

For example, a heading can look like ordinary text while sitting inside a hero image. Try selecting a word. If the browser selects the entire image instead, inspecting that image will not reveal the font used to create its pixels.

Inspect the exact text element

  1. Open the page and wait for its text to settle.
  2. Right-click the heading or paragraph you want, then choose Inspect.
  3. In Elements, select the smallest element containing that text. A nested span may have different styling from its parent.
  4. Open Computed and search for font. Note family, size, style, and weight.
  5. Clear the filter and inspect Rendered Fonts near the bottom of the panel.

Chrome documents the Rendered Fonts section in its font inspection example. That section helps distinguish a local font from a web font. If the interface differs in your Chrome version, look for the Computed panel within Elements.

Why the first font name may be wrong

A declaration such as font-family: "Studio Sans", Arial, sans-serif is a preference list. It does not prove that Studio Sans loaded. The browser may use a fallback, and different characters can come from different fonts. MDN’s font-family reference explains the ordered selection and character-level fallback.

Consider a card with English text followed by an emoji. Treat the emoji font as a separate observation, not evidence that the whole card uses it. Similarly, a page may use one family for headings and another for forms. Sample each role you intend to recreate.

Record a useful typography specimen

Use a short record like this original example when moving from inspection to implementation. These values are illustrative, not measurements of another website:

Role: card title
Sample: A calmer way to work
Rendered family: Inter
Weight: 600
Size: 24px
Line height: 30px
Letter spacing: -0.3px
Container width: 320px
State: desktop, default

The container width matters because it changes where a line wraps. A correct font inside the wrong width may look like a wrong font. Save the exact sample text, viewport, and the state of the component so you can repeat the comparison.

Download the typography audit worksheet and fill one row per role. If you are collecting more than type, use the website design-system audit to keep the measurements together.

Troubleshoot a font that still looks different

  • Wrong weight: compare the actual weight, not just a “bold” label in your editor.
  • Wrong line breaks: match text, width, font size, and letter spacing before changing the family.
  • Late loading: reload and watch whether the text changes after the initial render.
  • Different device: check the same page on the device where the mismatch occurs.
  • Different state: inspect the element after opening its menu or changing its tab.

When the computed value is surprising, trace the matching CSS rule and inherited styles. Our CSS inspection workflow explains how to find the declaration behind a visible result.

Turn the observation into your own type system

Choose a small set of text roles: page heading, section heading, paragraph, label, and code. Give each a deliberate size and spacing rule. You do not need to copy every one-off size found on the reference page; that often imports accidental inconsistencies into your own design.

Obtain font files from the creator or an authorized distributor and check the license before reuse. A font being downloadable by a browser is not evidence that you can redistribute it. Keep your inspection notes separate from the files you are licensed to ship.

For a wider visual handoff, combine this worksheet with the color palette extraction guide. The useful deliverable is a set of named text roles and verified styles, not a folder of unexplained font filenames.
