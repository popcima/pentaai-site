Match Native Controls to a Theme with color-scheme

Use color-scheme to declare supported native UI appearances. Keep custom tokens, selected theme and browser-managed controls consistent across light and dark.

By Penta AIPublished 18 November 20261 min read

In this guide

  1. Declare the scheme the selected theme supports
  2. Keep preference detection separate from support
  3. Review the full control inventory

Color-scheme tells the browser which color schemes an element can support. It can influence browser-managed controls and scrollbars, but it does not recolor every custom component. A page with dark backgrounds and bright native inputs often needs this declaration aligned with its actual theme.

Declare the scheme the selected theme supports

:root {
  color-scheme: light;
  --page: #f7f9f7;
  --text: #17251d;
}
:root[data-theme="dark"] {
  color-scheme: dark;
  --page: #142019;
  --text: #edf5ef;
}
body { background: var(--page); color: var(--text); }

This example assumes application code deliberately sets the theme attribute. It does not implement a theme picker or persistence. Compare a native text input, select and date field in both states, alongside a custom card using the same page tokens.

Reference: MDN color-scheme.

Keep preference detection separate from support

Prefers-color-scheme detects the user’s preference; color-scheme declares the schemes the element supports. Declaring light dark allows browser selection among supported schemes. It should not be used as a claim that a fixed light-only custom interface has already been designed for dark mode.

A deliberately light embedded section on a dark page may need its own light color scheme and matching custom foreground and background colors. Test that section’s descendants instead of changing the entire document to repair one field. Native styling still varies by browser and operating system.

Review the full control inventory

  • Check editable, disabled, focused and invalid fields.
  • Open native pickers and menus where supported.
  • Inspect custom icons and placeholder text against their actual surfaces.
  • Test user preference changes and an explicit application override.

Accent-color controls certain native control accents and is not interchangeable with color-scheme. Forced-colors mode is another separate review. Use the semantic theme-token guide for authored components and native accent styling for checkboxes and related controls. The resulting theme should be judged from the rendered task, not merely from the presence of a dark-mode declaration.
