Inputmode vs. Input Type: Pick the Right Mobile Keyboard

Match virtual keyboards to field data without confusing keyboard hints with validation. Use text for identifiers and test entry, paste and autofill.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Decide whether the value is a quantity
  2. Choose a hint that permits the required characters
  3. Review the complete entry path

The input type describes the control and influences its behavior. The inputmode attribute suggests a virtual keyboard. A numeric keyboard hint does not validate the value, and it does not make a textual identifier into a number.

Decide whether the value is a quantity

A quantity such as the number of copies can reasonably use a number control. A five-digit identifier may need its leading zero preserved and has no useful increment operation. Start with the data model, then choose the keyboard. Do not use type="number" merely because a field happens to contain digits.

<label for="code">Five-digit reference code</label>
<input id="code" name="code" type="text"
  inputmode="numeric" pattern="[0-9]{5}"
  maxlength="5" aria-describedby="code-help" required>
<p id="code-help">Enter all five digits, including any leading zero.</p>

This original example deliberately accepts only five ASCII digits. It is a reference-code field, not a universal postal-code template. The pattern and required attributes express browser validation separately from the keyboard hint. The server must also validate submitted values.

Reference: MDN inputmode reference.

Choose a hint that permits the required characters

Use email and telephone input types when those are the actual data being collected. For a decimal text field, inputmode="decimal" can request a decimal separator, but available keys vary across devices and locales. Numeric or decimal keyboards may omit a minus key, so a field that accepts negative values needs a real-device check.

Think beyond typing: people may paste a value, use autofill, dictate it or connect a hardware keyboard. Instructions should describe the accepted format, and errors should explain how to correct the value. A keyboard layout is a convenience, not an input-security boundary.

Review the complete entry path

  • Enter a leading-zero value and check the value sent to the server.
  • Paste an invalid value and verify a useful error message.
  • Try an empty submission and a value that is too long.
  • Check virtual keyboards on representative iOS and Android devices.
  • Test autofill and browser back navigation without silently losing the value.

Include the field’s type, inputmode, autocomplete purpose and validation rule in the handoff. Review autocomplete tokens independently: a keyboard hint does not tell the browser which saved personal detail belongs in a field.
