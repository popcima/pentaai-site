Use autocomplete Tokens for Clear Address Forms

Assign meaningful autocomplete tokens to address fields. Distinguish shipping and billing groups, retain labels and test autofill without changing stored user data.

By Penta AIPublished 28 October 20262 min read

In this guide

  1. Describe one address group
  2. Keep the token sequence meaningful
  3. Review the filled state

autocomplete tokens tell the browser what information a field expects. They complement a visible label and an appropriate input type; they do not replace either. For repeated address forms, use grouping tokens so a shipping address and a billing address are not treated as one undifferentiated set of fields.

Describe one address group

<fieldset>
  <legend>Shipping address</legend>
  <label for="ship-street">Street address</label>
  <input id="ship-street" name="ship-street"
    autocomplete="section-delivery shipping address-line1">
  <label for="ship-city">City</label>
  <input id="ship-city" name="ship-city"
    autocomplete="section-delivery shipping address-level2">
  <label for="ship-postal">ZIP or postal code</label>
  <input id="ship-postal" name="ship-postal"
    autocomplete="section-delivery shipping postal-code">
</fieldset>

The example keeps the postal code as text so leading zeros and nonnumeric formats can be represented. Adapt labels and the address structure to the markets you actually support. The token is postal-code even when the visible US label says ZIP code.

Reference: MDN: autocomplete attribute.

Keep the token sequence meaningful

Autocomplete values can be an ordered list: a section identifier, an optional grouping such as shipping or billing, and a field-purpose token. Use a different section identifier when there are multiple distinct address blocks of the same kind. Do not invent a token from the field’s internal database name.

The browser ultimately decides how to offer and apply autofill. A token is guidance, not a guarantee that every browser will populate the field in the same way. Inspect the markup first if a field receives the wrong kind of information, then test the supported browsers with controlled sample data.

Review the filled state

  • Check that labels remain visible after values are inserted.
  • Verify that shipping and billing fields remain independent.
  • Test leading zeros and the longest supported address values.
  • Confirm that autofilled values reach the application’s validation and submission logic.

Use a test profile or explicitly provided sample details for QA; do not alter someone’s saved addresses merely to exercise the form. If the design changes the appearance of autofilled controls, review text contrast and focus as well. The handoff should pair each visible label with its field purpose, token sequence and expected validation behavior.
