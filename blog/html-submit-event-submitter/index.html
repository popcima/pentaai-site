Identify Which Button Submitted a Multi-Action Form

Use SubmitEvent.submitter for forms with multiple actions. Preserve button name and value data, handle missing submitters and test Enter-key submission.

By Penta AIPublished 18 November 20261 min read

In this guide

  1. Give actions explicit data values
  2. Keep server actions and UI actions aligned
  3. Test beyond clicking both buttons

A form can have multiple submit buttons with different action values. Read event.submitter in the form’s submit handler to identify the initiating control. Checking only the last button clicked is fragile because submission can also begin through a keyboard or programmatic path.

Give actions explicit data values

<form id="review-actions">
  <label for="review-name">Name</label>
  <input id="review-name" name="name" required>
  <button type="submit" name="intent" value="save">Save</button>
  <button type="submit" name="intent" value="preview">Preview</button>
</form>
const form = document.querySelector('#review-actions');
form.addEventListener('submit', event => {
  event.preventDefault(); // Local diagnostic fixture only.
  const submitter = event.submitter;
  const data = submitter
    ? new FormData(form, submitter)
    : new FormData(form);
  console.log(data.get('intent'));
});

Both actions in this fixture use normal validation. The two-argument FormData constructor includes the named submitter’s entry. Building FormData from the form alone does not preserve that clicked button’s name/value pair. Use specimen values for diagnostics rather than logging private form data.

Reference: MDN SubmitEvent.submitter.

Keep server actions and UI actions aligned

A button can override submission attributes such as the destination with formaction. Decide whether the native form transport or a JavaScript handler owns that routing. A custom fetch handler must deliberately preserve the intended behavior; it does not automatically honor every attribute merely because the DOM contains it.

Reference: MDN button submission attributes.

Handle a missing submitter explicitly according to the product contract. Do not guess that preview or publish was intended. The server should allow only recognized action values and independently check permissions before acting.

Test beyond clicking both buttons

  • Press Enter from the text field and inspect the resulting intent.
  • Call requestSubmit with a specific submit button.
  • Try invalid input before each action.
  • Confirm duplicate activation cannot accidentally perform an action twice.

If a helper action should never submit, use type="button" instead. Keep this pattern for actions that genuinely share the form’s submission and validation lifecycle.
