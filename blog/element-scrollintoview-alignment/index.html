Reveal an Element with Deliberate Scroll Alignment

Choose start, center or nearest alignment for scrollIntoView. Review nested scroll containers, sticky headers and motion without confusing scrolling with focus.

By Penta AIPublished 18 November 20262 min read

In this guide

  1. Start with minimal alignment movement
  2. Inspect every scrolling ancestor
  3. Keep motion and focus intentional

ScrollIntoView asks ancestor containers to reveal an element. Its alignment options control where that element should land; they do not move keyboard focus by themselves. Use a visible task, such as revealing a selected row, to decide whether minimal movement or a consistent landing position is appropriate.

Start with minimal alignment movement

const row = document.querySelector('[data-selected-row]');
row.scrollIntoView({
  behavior: 'instant',
  block: 'nearest',
  inline: 'nearest'
});

This fixture avoids animated scrolling and asks for the nearest alignment along both axes. Test it when the row is above, below and already inside the visible region. Compare block start or center if the task requires a specific reading position rather than the smallest useful adjustment.

Reference: MDN scrollIntoView options.

Inspect every scrolling ancestor

A row inside a scrolling panel can affect both that panel and the page. Record which containers move and verify that a surrounding heading or toolbar does not disappear unexpectedly. Do not assume the method only changes the nearest scroll container without explicitly checking the supported API options and behavior.

A sticky header can cover the landing position. Apply an appropriate scroll margin to the target and test the actual header height at the relevant breakpoint. A fixed offset copied from desktop may be wrong when navigation wraps on a smaller screen.

.review-row { scroll-margin-block-start: 5rem; }

Keep motion and focus intentional

  • Reveal a target near each edge of the scroll area.
  • Test a target taller than the available viewport.
  • Review nested scrolling and enlarged text.
  • Confirm keyboard focus remains where the task expects it.

If you choose smooth behavior, provide a reduced-motion path and avoid repeated animation as state updates. If the user also needs focus moved, make that a separate decision with a focusable destination; scrolling alone is not an accessible focus-management strategy.

Use the scroll-margin guide to handle landing offsets and the focus guide to coordinate an already-visible destination. Record the reason for the alignment so a later animation change does not obscure the original task.
