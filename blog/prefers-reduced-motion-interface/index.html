Respect Reduced Motion Without Hiding Interface Feedback

Use prefers-reduced-motion to reduce nonessential movement while keeping clear state changes. Review CSS transitions, JavaScript animation and loading feedback.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Enhance a stable button state
  2. Inventory motion by purpose
  3. Test the whole task with the preference enabled

Reduced motion should preserve the information a transition communicates while removing unnecessary movement. A panel can appear without sliding across the screen, and a saved state can remain visible without a bouncing confirmation. Start with the usable static state, then add motion only where the user has not requested a reduction.

Enhance a stable button state

.action {
  background: #173f86;
  color: white;
  border: 2px solid transparent;
}
.action:hover { background: #102f65; }
.action:focus-visible { outline: 3px solid #2878dd; outline-offset: 3px; }
@media (prefers-reduced-motion: no-preference) {
  .action { transition: transform 150ms ease; }
  .action:hover { transform: translateY(-2px); }
}

The color change and focus indicator do not depend on animation. The small lift is an optional decoration. This example avoids a hidden initial state: if the media query never matches, the button is still present and usable.

The MDN media-feature reference describes the reduce and no-preference values. The preference concerns motion; it does not instruct you to remove content, stop progress reporting or eliminate every visual distinction between states.

Inventory motion by purpose

MotionReduced-motion alternative
Large panel slideShow the panel immediately.
Decorative parallaxKeep the artwork stationary.
Animated progress illustrationRetain a text status and measured progress if available.
Smooth anchor scrollingUse immediate scrolling.

Review CSS and JavaScript separately. A CSS media query does not automatically stop an animation driven by a canvas library or a timer. For scripted animation, use matchMedia to read the same preference and respond if it changes. Check the animation library’s own configuration rather than layering contradictory overrides on top.

Avoid a blanket rule that forces every duration to an extremely short value without testing behavior. Some applications incorrectly depend on animation-end events to finish a state change. Fix that dependency or preserve the necessary event handling; an accessibility preference should not leave a dialog half-open or a loading control permanently disabled.

Test the whole task with the preference enabled

Enable reduced motion in your operating system or browser emulation, reload, and complete a task from start to finish. Open navigation, submit a sample form, change tabs and follow an anchor. Verify that status messages remain understandable, keyboard focus remains visible and content does not wait for an animation that no longer runs.

Then switch the preference while the page is open if your application supports live changes. Record the expected behavior for each animated component in the handoff. A useful acceptance statement is “the panel opens immediately and focus moves to its first meaningful control,” which can be checked independently of the decorative transition.
