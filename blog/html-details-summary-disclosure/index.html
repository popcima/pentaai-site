Use details and summary for Simple Disclosure Panels

Build a native disclosure with details and summary. Style its open state, avoid Boolean-attribute mistakes and review labels, focus and essential content.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Start with native markup
  2. Understand the open attribute
  3. Review content and interaction

Use details and summary when someone should be able to reveal a small piece of supporting information in place. The browser provides the basic open-and-close interaction. This is a useful starting point for export notes or optional explanations, provided the summary clearly describes what will be revealed.

Start with native markup

<details class="export-note">
  <summary>What is included in this sample export?</summary>
  <p>The sample includes spacing labels and color values.
     It does not include source images.</p>
</details>
.export-note { border: 1px solid #b7beca; border-radius: .75rem; }
.export-note summary { padding: 1rem; cursor: pointer; }
.export-note p { padding-inline: 1rem; }
.export-note[open] { background: #f3f6fb; }
.export-note summary:focus-visible {
  outline: 3px solid #174fa0;
  outline-offset: 3px;
}

The sample export is hypothetical content, not a statement about a specific product’s output. Replace it with the actual information your interface needs. Keep summary as the first child and preserve its native affordance unless you provide an equally understandable replacement.

Reference: MDN: details element.

Understand the open attribute

open is Boolean: its presence opens the panel. Writing open="false" still leaves it open. To close it in markup, remove the attribute. If scripting is needed, set the element’s open property to false rather than treating the string “false” as a closed state.

A shared name can group disclosures so opening one closes another in supporting browsers. Choose that behavior intentionally. Keeping several panels open may help readers compare answers; closing a previous answer automatically can interrupt that task. Test the grouped behavior against your browser requirements before depending on it.

Review content and interaction

  • Use a meaningful summary instead of repeated “More” labels.
  • Tab to the summary and toggle the panel with the keyboard.
  • Check that the focus indicator survives the rounded container styling.
  • Read the open and closed state with the assistive technologies you support.

Do not place the only explanation of a critical error inside a closed panel. A disclosure is best for supplementary detail, not information someone must notice to finish a form. Also avoid nesting unrelated action buttons inside the summary; they create competing interactions in the same target.

For handoff, capture both states and specify the default. Review a long summary at a narrow width: the text should wrap without colliding with the marker, and the expanded body should remain readable without a fixed-height crop.
