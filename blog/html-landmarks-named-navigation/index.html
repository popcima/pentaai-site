Use HTML Landmarks and Name Multiple Navigation Regions

Organize a page with main, nav, header and footer. Give distinct navigation regions useful names and verify the resulting accessibility tree.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Map the page’s major regions
  2. Give names that describe the destination group
  3. Inspect the result, not just the tags

Use native HTML landmarks to expose the major regions of a page, then give repeated regions distinct names when their purposes differ. A reader should be able to find the main content or a particular navigation group without stepping through every link.

Map the page’s major regions

<header>
  <a href="/">Example workspace</a>
  <nav aria-label="Primary">...</nav>
</header>
<nav aria-label="Project">...</nav>
<main id="main-content">
  <h1>Project overview</h1>
  <!-- The unique content for this page -->
</main>
<footer>...</footer>

In this example, Primary contains site-wide destinations while Project contains links for the selected project. Keep one visible main region for the page. A site-level header and footer provide different context from a header nested inside an article; the nested header is not automatically a site-wide banner landmark.

Reference: W3C WAI page regions tutorial.

Give names that describe the destination group

Prefer “Project” and “Primary” over “Navigation 1” and “Navigation 2.” Assistive technology can already announce the navigation role, so repeating that word in every name is usually unnecessary. If a visible heading names the region, connect it with aria-labelledby instead of maintaining a second label that can drift out of date.

<nav aria-labelledby="resources-title">
  <h2 id="resources-title">Resources</h2>
  <ul>
    <li><a href="/guides/">Guides</a></li>
    <li><a href="/support/">Support</a></li>
  </ul>
</nav>

Do not turn every card and decorative wrapper into a named region. A crowded landmark list makes the major boundaries harder to locate. For the example page, write down what a user would accomplish by jumping to each proposed landmark; remove regions that have no useful answer.

Inspect the result, not just the tags

  • Check the accessibility tree for the expected landmark roles and names.
  • Open the mobile menu and confirm hidden desktop navigation does not remain available unexpectedly.
  • Navigate by landmarks with a screen reader, then use the links inside each region.
  • Follow the skip link and verify it reaches the intended main content.

Landmarks, heading levels and the skip-link target should describe the same page organization. If they disagree, resolve the information structure before polishing spacing. This is a navigation aid, not a replacement for meaningful headings or clear link labels.
