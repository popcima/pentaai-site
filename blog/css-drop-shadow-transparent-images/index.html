Drop-shadow vs. Box-shadow for Transparent Images

Choose a shadow that follows a transparent image’s silhouette. Compare filter syntax, blur behavior and clipping before reusing a card elevation token.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Compare the same asset with two shadow models
  2. Apply the filter to the intended content
  3. Check clipping and nearby elements

Use filter: drop-shadow() when the shadow should follow the opaque parts of a transparent image. Use box-shadow when the shadow belongs to the element’s box, such as a card surface. A transparent PNG or SVG makes the difference easier to see than a rectangular photograph.

Compare the same asset with two shadow models

.asset-box {
  box-shadow: 0 8px 16px rgb(16 24 40 / 20%);
}
.asset-shape {
  filter: drop-shadow(0 8px 8px rgb(16 24 40 / 20%));
}

These are separate example starting values, not mathematically identical effects. Drop-shadow’s third length controls a blur standard deviation, while box-shadow uses a blur-radius parameter. Copying all the same numbers does not promise the same softness.

Reference: MDN drop-shadow() reference.

The filter follows the rendered alpha shape. If the source image contains an opaque white rectangle around the artwork, the shadow will follow that rectangle too. Open the asset against a contrasting background to verify transparency before trying to repair the effect with CSS.

Apply the filter to the intended content

A filter on a wrapper processes that element and its rendered contents as a group. If the wrapper includes a background and a text label, the shadow may describe more than the icon silhouette. Move the effect to the intended image when those other parts should remain unaffected.

Drop-shadow does not accept box-shadow’s spread length or inset keyword. Multiple drop-shadow functions are space-separated within filter, not comma-separated box-shadow layers. Filter order also matters, so inspect the complete filter declaration before replacing a single effect.

Check clipping and nearby elements

  • Compare the image with the filter disabled to reveal the original alpha edges.
  • Inspect ancestors for overflow clipping near the shadow.
  • Try the effect against both light and dark surfaces.
  • Review overlap with neighboring controls and any changed stacking behavior.
  • Check a smaller responsive image size before adopting the values as a token.

A non-none filter can establish a stacking context, which may explain an overlap change after a visual edit. Use the stacking-context inspection guide if z-index adjustments stop behaving as expected. For ordinary panel elevation, keep the box-shadow workflow; transparency-aware shadows solve a different task.
