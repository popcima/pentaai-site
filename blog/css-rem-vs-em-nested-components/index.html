rem vs. em: Diagnose Nested Component Scaling

Trace rem and em values to their sizing reference. Prevent compounded font sizes while letting component padding scale with its own text.

By Penta AIPublished 15 November 20262 min read

In this guide

  1. Calculate a small nested example
  2. Choose the relationship you want to preserve
  3. Stress the component hierarchy

A rem length normally follows the root element’s font size. An em length normally follows the element’s computed font size; when used for font-size itself, em refers to the inherited font size. That distinction explains why nested text can compound while padding scales with the local text.

Calculate a small nested example

html { font-size: 100%; }
.panel { font-size: 1.25em; }
.panel .label { font-size: 1.25em; }
.action {
  font-size: 1rem;
  padding: .5em 1em;
}

If the root computes to 16px and no other ancestor changes the size, the panel becomes 20px and its label becomes 25px. The action uses the root-based 16px text, with 8px by 16px padding. These numbers illustrate the relationships; they are not a recommendation to force the root to 16px.

Reference: MDN CSS length units reference.

Choose the relationship you want to preserve

Root-relative text roles can help avoid unintended compounding across nested components. Local em padding can be useful when a button should grow proportionally with its own label. Neither unit automatically guarantees a responsive or accessible layout: fixed containers can still clip scaled text.

Inspect the computed font-size on the element and its ancestors before converting units. A value that looks surprising may come from an inherited component size, a browser preference or a variant class. Replacing every em with rem without tracing that chain can remove intentional local scaling.

Remember that children inherit computed values. A relative value declared on a parent is not always re-evaluated against each child’s font size. If spacing should follow the child’s text role, place the declaration on the element that owns that role.

Stress the component hierarchy

  • Render the component on the page root and inside a larger-text panel.
  • Nest it two levels deep and compare computed sizes.
  • Increase the browser’s default font size and test text zoom.
  • Try long labels that wrap rather than only a single short word.
  • Check that icons and padding scale according to the intended relationship.

Record the reference for each token: root text size, component text size or another layout dimension. For a fluid heading, combine this decision with the clamp typography workflow. A unit choice is most useful when another developer can explain what should change together.
