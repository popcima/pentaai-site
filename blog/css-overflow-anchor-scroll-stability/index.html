Investigate Scroll Jumps Before Disabling Anchoring

Use overflow-anchor as a targeted diagnostic for scroll adjustments. Separate browser anchoring from layout shifts and script-driven scrolling before choosing a fix.

By Penta AIPublished 19 November 20262 min read

In this guide

  1. Reproduce one insertion above the reading point
  2. Identify which mechanism moved the view
  3. Keep the opt-out narrow

Browsers can adjust scroll position to keep the reader’s location stable when content changes above it. Overflow-anchor provides an opt-out from that scroll-anchoring behavior. Use it for a measured conflict, not as a global cure for every unexpected jump.

Reproduce one insertion above the reading point

.changing-banner {
  overflow-anchor: none;
}

Create a local fixture with a changing banner above several paragraphs. Scroll to a known paragraph, change the banner’s height and compare the result with and without the rule. The property excludes that region from anchoring selection; it does not reserve space or prevent the banner from changing layout.

Reference: MDN overflow-anchor.

Identify which mechanism moved the view

A script calling scrollIntoView, a focus operation, browser anchoring and a visible layout shift can produce superficially similar symptoms. Record the active element, scroll position and content change together. Disable one suspected behavior at a time rather than changing several overflow and height rules simultaneously.

Prefer stable space for predictable media and banners when that solves the underlying problem. If your application deliberately manages scrolling, such as a carefully implemented message view, document when it follows new content and when it preserves the reader’s position. An anchoring opt-out alone does not implement that policy.

Keep the opt-out narrow

  • Test a reader at the top, middle and bottom of the region.
  • Insert and remove content above the visible item.
  • Check keyboard focus and explicit navigation separately.
  • Review browsers in the project’s actual support policy.

Applying none broadly can remove helpful behavior elsewhere. A descendant cannot simply opt back into anchoring once an ancestor has opted the subtree out. Limit the rule to the region whose participation is causing the observed conflict and keep a record of that reproduction.

Use layout-shift diagnosis to find unstable geometry and scroll alignment inspection for explicit script movement. The repair should explain why the view moved and which behavior now owns scroll stability.
