Make an Inactive Panel Noninteractive with inert

Use inert for an entire inactive region while managing focus and visible state. Distinguish it from hidden content, disabled fields and access control.

By Penta AIPublished 28 October 20262 min read

In this guide

  1. Keep the activation control outside the region
  2. Choose the right kind of unavailability
  3. Review both directions of the transition

The inert attribute prevents interaction with an element and its descendants and removes the region from keyboard and accessibility navigation. It can help when an inactive panel remains visually present during a state change. Because the content also becomes unavailable to assistive technology, do not use it on information people still need to read.

Keep the activation control outside the region

<button id="toggle-editor" type="button">Enable editor</button>
<p id="editor-state">Editor is inactive.</p>
<section id="editor" inert>
  <label for="project-note">Project note</label>
  <input id="project-note">
</section>
const toggle = document.querySelector("#toggle-editor");
const editor = document.querySelector("#editor");
toggle.addEventListener("click", () => {
  const enable = editor.inert;
  if (!enable) toggle.focus();
  editor.inert = !enable;
  toggle.textContent = enable ? "Disable editor" : "Enable editor";
  document.querySelector("#editor-state").textContent =
    enable ? "Editor is active." : "Editor is inactive.";
  if (enable) document.querySelector("#project-note").focus();
});

This small example keeps the state description outside the inert region. Before making the editor inactive, focus is placed on the external toggle. When enabled, focus enters the first field. Adapt that focus policy to the actual task rather than automatically moving focus for every state update.

Reference: MDN: inert.

Choose the right kind of unavailability

inert does not automatically hide or dim the region. Add a clear visual treatment when the panel remains visible. If only an individual form control is unavailable, native disabled or readonly behavior may better describe the requirement. If the entire section should disappear, a visibility mechanism may already provide the needed exclusion.

Review both directions of the transition

  • Enable the panel and reach every intended control.
  • Disable it and confirm focus is not left inside.
  • Check that the activation control remains reachable.
  • Verify that the inactive appearance is understandable without relying only on color.

As a Boolean attribute, inert is active when present; inert="false" does not remove it. Use the DOM property or remove the attribute when enabling the region. Finally, this is an interface behavior, not an authorization boundary. The application must still enforce any permissions and data access independently of what the browser allows someone to click.
