Choose Paired Colors with light-dark and the Active Scheme

Use light-dark with an explicit color-scheme policy, compare inherited and forced component schemes, and keep fallback colors readable without the function.

By Penta AIPublished 24 November 20261 min read

In this guide

  1. Provide a base pair and an enhanced pair
  2. Inspect the scheme rather than only the system preference
  3. Test both branches and the fallback

Light-dark chooses between two colors using the element’s active color scheme. A pair of colors alone is not a complete theme policy: inspect color-scheme on the element and its ancestors when the unexpected branch appears.

Provide a base pair and an enhanced pair

 .review-surface { background: #fff; color: #18251e; }
@supports (color: light-dark(black, white)) {
  :root { color-scheme: light dark; }
  .review-surface {
    background: light-dark(#fff, #14201a);
    color: light-dark(#18251e, #edf5ef);
  }
  .review-surface.always-light { color-scheme: light; }
}

The support block declares that both schemes are supported and supplies foreground and background together. The always-light variant selects a light scheme locally. The base declarations remain a usable pair where this function is unavailable.

Reference: MDN CSS light dark color scheme.

Inspect the scheme rather than only the system preference

A local color-scheme declaration can change which branch the element uses even when the operating system prefers dark. The property can also influence native controls and other browser-rendered surfaces. Record inherited and local values while diagnosing a mismatch.

Keep an explicit application theme choice consistent with this policy. A separate class that changes only one background can leave light-dark text following another scheme. Group related semantic colors so the same component does not mix incompatible assumptions.

Test both branches and the fallback

Compare system light and dark preferences, then apply the local light variant in each. Inspect form controls embedded in the surface and any overlay that escapes its normal subtree. Disable the enhancement to verify the static fallback pair.

Check actual contrast for text, borders and icons in every supported state. Selecting a dark or light color branch does not validate the palette, and it does not replace a forced-colors review or a persistent user theme setting.

Align native controls with the theme. Organize semantic theme colors.
