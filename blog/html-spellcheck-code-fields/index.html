Choose Spellchecking by the Kind of Text Being Edited

Keep spelling assistance for prose while disabling it for code-like identifiers, and verify the actual browser behavior without treating it as validation.

By Penta AIPublished 20 November 20261 min read

In this guide

  1. Give prose and code separate policies
  2. Do not confuse spelling with correctness
  3. Review editing, pasting and language changes

A CSS token editor and a review-notes field contain different kinds of text. Spellcheck can be useful for prose and distracting for identifiers. Set the attribute narrowly on each field instead of disabling assistance across the entire page.

Give prose and code separate policies

<label for="token">CSS token name</label>
<input id="token" name="token" spellcheck="false" value="--surface-card">
<label for="notes">Review notes</label>
<textarea id="notes" name="notes" spellcheck="true" lang="en"></textarea>

The token example is deliberately code-like; a spelling underline under surface-card would not indicate a malformed CSS custom property. The notes field contains ordinary English. Keep visible labels in place so the browser’s spelling feedback is not the only clue about what belongs in either control.

Reference: MDN spellcheck.

Do not confuse spelling with correctness

Spellcheck is an enumerated attribute: false is meaningful, rather than the presence of the attribute automatically enabling it. Omitted behavior depends on the element, inheritance and browser. A true setting is a request for available checking, not a guarantee of identical dictionaries or underlines on every device.

Spelling feedback does not enforce your application’s token syntax, and it is separate from autocomplete or keyboard correction. Validate identifiers using explicit rules. For sensitive fields, review whether enhanced spelling services could process the content; disabling a field’s spellcheck is not a general data-security guarantee.

Review editing, pasting and language changes

Type a deliberately misspelled word into notes, then paste a valid token into its field. Test with browser spelling enabled and disabled. Check a second content language if the application supports it, and retain clear errors for invalid identifiers regardless of spelling settings. Record the browser settings when a reviewer reports unexpected underlines.

Use language markup accurately and keep persistent field labels independent of editing assistance.
