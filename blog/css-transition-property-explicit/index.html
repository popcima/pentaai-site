Replace transition: all with an Intentional Property List

Choose exactly which CSS properties should animate. Prevent later layout edits from gaining accidental transitions and keep focus and reduced-motion behavior clear.

By Penta AIPublished 15 November 20262 min read

In this guide

  1. Define the transition on the base state
  2. Inspect the values that actually change
  3. Test interruption, not only a clean hover

List the properties you intend to animate instead of using transition: all by default. An explicit list makes a component’s motion easier to review and prevents an unrelated future change, such as width or padding, from unexpectedly inheriting the same timing.

Define the transition on the base state

.action {
  background-color: #174fa0;
  color: white;
  transition: background-color 160ms ease, color 160ms ease;
}
.action:hover { background-color: #123d7b; }
.action:focus-visible {
  outline: 3px solid #174fa0;
  outline-offset: 3px;
}
@media (prefers-reduced-motion: reduce) {
  .action { transition: none; }
}

The timing values are an illustrative starting point. A base-state transition can apply as the hover state is entered and left. The focus outline appears immediately because it is not in the transition list. Review that distinction as part of the interaction rather than animating every visible change.

Reference: MDN transition-property reference.

Inspect the values that actually change

A transition needs a change between values. If nothing moves, compare the before and after computed values, the duration and the winning declaration. A property name in transition-property does not itself change that property or guarantee that every pair of values interpolates.

Be specific with shorthand properties too. Listing background can include multiple animatable background longhands, while background-color makes the intent narrower. When property, duration and delay lists have different lengths, CSS list matching can make the result less obvious; a repeated shorthand entry per intended property is often easier to review.

Test interruption, not only a clean hover

  • Enter and leave the control quickly, then repeat several times.
  • Focus the control from the keyboard without a pointer hovering over it.
  • Try a busy or disabled state that interrupts the visual change.
  • Enable reduced motion and confirm the state remains understandable.
  • Inspect a component variant that changes size or spacing.

Avoid making task completion depend solely on a transitionend event: a canceled transition or a reduced-motion path needs correct application behavior too. The visual effect should support a state change that the interface can represent immediately when necessary.

Use the DevTools animation inspection workflow to compare the actual timing, then save only the intentional property changes. A smaller transition declaration is useful when it expresses a clearer component contract.
