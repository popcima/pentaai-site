Choose Cursor Feedback That Matches the Real Interaction

Use cursor keywords and custom-image fallbacks deliberately, inspect inherited cursor rules, and keep unavailable or draggable behavior in the interaction code.

By Penta AIPublished 23 November 20261 min read

In this guide

  1. Keep a usable keyword fallback
  2. Check inherited and native cursor behavior
  3. Test unavailable assets and interrupted interactions

A cursor communicates a pointer interaction; it does not implement that interaction. Setting not-allowed does not disable a button, and grab does not make an element draggable. Review the cursor together with the control’s real behavior and visible state.

Keep a usable keyword fallback

.inspect-surface {
  cursor: url("/assets/inspect-cursor.png") 8 8, crosshair;
}
.inspect-surface.is-panning { cursor: grabbing; }
button:disabled { cursor: not-allowed; }

The image URL is a project placeholder that must be replaced with a real cursor asset before use. The 8 8 hotspot identifies the active point within that image. If the image cannot be used, the final crosshair keyword supplies a fallback. The is-panning class needs real interaction code to manage it.

Reference: MDN CSS cursor fallback interaction.

Check inherited and native cursor behavior

Cursor is inherited, so a broad rule on a wrapper can reach nested text or controls. A crosshair covering an editable field can communicate the wrong action. Inspect the actual hit-tested element and its computed cursor before changing a global style.

Browsers impose limits on custom cursor image sizes and supported formats. Keep the asset small and test the target platforms rather than assuming an arbitrary SVG or large bitmap will work everywhere. Touch interfaces may have no mouse cursor at all.

Test unavailable assets and interrupted interactions

Block the custom image and confirm the keyword fallback remains sensible. Move the pointer over nested controls and verify text selection, links and buttons still communicate their expected interactions. Test a panning cancellation so the grabbing state does not remain after the operation ends.

For an unavailable action, pair the appropriate native disabled state or deliberate accessible disabled behavior with an explanation where needed. Never rely on the cursor as the only indication: keyboard and touch users need the same underlying state and usable feedback.

Implement a discoverable unavailable action. Inspect the element receiving pointer hits.
