Use Hover and Pointer Queries Without Hiding Actions

Adapt optional hover styling to input capabilities. Keep controls available on touch, keyboard and hybrid devices instead of treating screen width as input type.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Build a complete baseline interaction
  2. Understand primary input and hybrid devices
  3. Test the task through each input path

Use hover and pointer media queries to adapt optional styling to the primary pointing input. Keep essential controls available without hover. A narrow viewport is not proof of touch input, and a wide viewport is not proof that a mouse is being used.

Build a complete baseline interaction

.action {
  min-height: 2.75rem;
  padding: .65rem 1rem;
}
.action:focus-visible {
  outline: 3px solid #174fa0;
  outline-offset: 3px;
}
@media (hover: hover) and (pointer: fine) {
  .action:hover { background: #e7f0ff; }
}

The button remains visible and usable without the media query. The example height is a design choice, not a claim that one dimension alone establishes accessibility. Focus styling stays outside the hover condition so keyboard users do not depend on pointing-device detection.

Reference: MDN hover media feature.

Reference: MDN pointer media feature.

Understand primary input and hybrid devices

Hover asks whether the primary pointing mechanism can conveniently hover. Pointer describes the accuracy of the primary pointing mechanism. The any-hover and any-pointer variants describe capabilities among available pointing mechanisms, which may include more than one device.

A touchscreen laptop can have both touch and a mouse. Discovering that some device can hover does not mean the user is currently using it. Do not use any-hover to make an essential delete control available only when the pointer enters a card. Keep the action visible, or provide an explicit tap and keyboard path.

Test the task through each input path

  • Use keyboard-only navigation and confirm every action can be reached.
  • Tap the interface and verify the first tap performs a predictable action.
  • Move the pointer into and out of dropdowns without losing their content.
  • Check a hybrid device with more than one pointing mechanism.
  • Inspect enlarged text and long labels without shrinking targets.

For a disclosure, define an explicit trigger and state. A hover color may enhance the trigger, but hover should not be the only way to discover or operate its content. Forced states in DevTools help inspect CSS; they cannot establish that real touch or keyboard interaction works.

Record the input capability you tested instead of labeling screenshots “mobile” and “desktop” alone. Use the forced-state inspection workflow for styling, followed by real interaction checks for behavior.
