Observe Invalid Form Controls from a Capture Listener

Catch invalid events at a form with capture enabled, distinguish validation checks from submission, and preserve useful native feedback while diagnosing errors.

By Penta AIPublished 24 November 20261 min read

In this guide

  1. Capture without suppressing the browser feedback
  2. Distinguish the check from the final submit event
  3. Review errors as a complete interaction

The invalid event fires on a control when a validity check finds that control invalid. It does not bubble like an ordinary click. A listener on the form can observe those events during capture, which is useful when investigating which controls block submission.

Capture without suppressing the browser feedback

<form id="review-form">
  <label for="review-title">Review title</label>
  <input id="review-title" name="title" required>
  <button>Save review</button>
</form>
<script>
const form = document.querySelector('#review-form');
form.addEventListener('invalid', event => {
  console.log('Invalid control:', event.target.id);
}, { capture: true });
</script>

Try submitting with the field empty. The form-level capture listener records the invalid control while the browser keeps its normal validation behavior. The handler intentionally does not call preventDefault or replace the validation message.

Reference: MDN HTML invalid event capture.

Distinguish the check from the final submit event

A failed interactive validation can prevent a submit event from reaching a submit handler. Logging only submit can therefore miss the reason nothing appears to happen. CheckValidity also triggers invalid events for failing controls, while reportValidity additionally requests visible reporting.

Several controls can produce separate invalid events in one validation pass. A diagnostic should not mistake that for several submission attempts. Avoid calling another validity check from inside the invalid listener without a clear guard, since that can trigger repeated events.

Review errors as a complete interaction

Test an empty required value, an invalid format and a corrected value. Confirm stale custom errors are cleared and the reader can identify and reach each problem. Inspect any novalidate or formnovalidate settings when the expected events do not occur.

If replacing native reporting with a custom error summary, implement focus, field associations and clear messages deliberately. Event capture alone supplies observations; it does not create an accessible error experience or replace server-side validation.

Clear stale custom validity messages. Connect visible errors to their fields.
