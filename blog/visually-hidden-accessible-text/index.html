Hide Supporting Text Visually Without Losing Its Accessible Name

Use a visually hidden text helper for an icon control’s name. Distinguish it from display:none, avoid duplicate naming and keep focus indicators visible.

By Penta AIPublished 28 October 20262 min read

In this guide

  1. Name a compact close control
  2. Keep the hiding methods distinct
  3. Review the control in context

Visually hidden text can give an icon-only control a meaningful accessible name while keeping its compact appearance. The text remains available to assistive technology even though it is clipped visually. Use this deliberately; ordinary instructions that everyone needs should usually remain visible.

Name a compact close control

<button type="button" class="close-preview">
  <span aria-hidden="true">×</span>
  <span class="visually-hidden">Close preview</span>
</button>
.visually-hidden {
  position: absolute;
  inline-size: 1px;
  block-size: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}

The button remains a visible, focusable native control. Only its explanatory text is clipped, and the decorative multiplication symbol is hidden from the accessibility tree. Connect the close action in the application separately; this specimen demonstrates naming and styling.

Reference: W3C: visually hiding supplemental text with CSS.

Keep the hiding methods distinct

display: none and visibility: hidden remove text from normal accessibility exposure, so they are not substitutes for this naming pattern. aria-hidden also excludes content from the accessibility tree. Do not put aria-hidden on the span that supplies the control’s only name.

Avoid adding another conflicting name with aria-label unless you have a clear naming strategy. A visible “Close” label plus unnecessary hidden repetition can also make the announced name awkward. Inspect the final accessible name rather than assuming every extra label improves it.

Review the control in context

  • Tab to the button and confirm a visible focus indicator.
  • Inspect its computed accessible name.
  • Test it with the screen readers and browsers you support.
  • Check that the hidden text does not create page overflow when zoomed.

Do not apply a static visually-hidden helper to a focusable link that should reveal itself when focused. A skip link, for example, needs its own visible-on-focus treatment. Keeping a focused interactive element invisible creates a different problem from hiding a supporting text span.

For handoff, specify the accessible name alongside the icon and action. If users are likely to misunderstand the symbol, prefer a visible text label rather than expecting assistive text to solve the visual usability problem.
