Build a Consistent Border Radius System in CSS

Choose useful radius tokens for buttons, cards and nested surfaces. Inspect real corners, avoid clipping focus rings, and document intentional exceptions.

By Penta AIPublished 26 October 20263 min read

In this guide

  1. Identify the shape, not just the number
  2. Create named roles
  3. Treat nested corners as a geometry problem
  4. Separate rounding from clipping
  5. Review awkward states

A border radius system gives repeated components a consistent shape without forcing every object to have identical corners. Start with a few roles, such as controls, cards and floating panels, then test them at their actual dimensions. A 12px radius looks very different on a small input and a large content card.

Inspect the computed corner values of a reference rather than estimating from a scaled screenshot. Record the component width and height too. If the value is a percentage, the apparent curve can change when the box changes size.

Identify the shape, not just the number

The border-radius reference explains circular and elliptical corners, individual corner values and percentage behavior. Check whether the component uses one value for all corners, separate horizontal and vertical radii, or individual corner overrides.

Shape roleExample starting valueCheck
Compact field0.5remDoes the curve crowd the label or icon?
Content card1remDoes it match the card’s size and padding?
Floating panel1.25remDoes it feel related to the cards?
Pill control999pxDoes it stay comfortable when its label wraps?

These example values are a proposed system, not an industry standard. Compare a small set on a component sheet and choose the set that suits your product. If each component requires a slightly different value, review whether its dimensions or spacing are inconsistent before adding another token.

Create named roles

:root {
  --radius-control: .5rem;
  --radius-card: 1rem;
  --radius-panel: 1.25rem;
  --radius-pill: 999px;
}
.field { border-radius: var(--radius-control); }
.card { border-radius: var(--radius-card); }
.dialog { border-radius: var(--radius-panel); }

Keep shape and spacing separate even when they happen to share a number. Increasing card padding should not unexpectedly change input corners. A shared primitive scale can support both, but role aliases should make each design decision explicit.

Treat nested corners as a geometry problem

An inner rounded surface with the same radius as its outer container can produce uneven-looking corner spacing. As a starting approximation for evenly inset circular curves, reduce the inner radius by the inset. For a 24px outer radius and an 8px inset, try a 16px inner radius, then inspect the result.

That subtraction is a design starting point, not a universal CSS formula. Borders, unequal padding and elliptical corners complicate the relationship. Test the real component instead of globally applying a calculation to every nested element.

Separate rounding from clipping

Rounded borders do not automatically solve every child-content clipping problem. An image may need a matching radius or a dedicated clipping wrapper. Before adding overflow: hidden to the entire card, check whether it contains focus outlines, menus or tooltips that should extend beyond the edge.

For media cards, let the media region handle image clipping and leave the interactive shell free to show its focus treatment. The shadow guide uses a similar separation between the element that clips content and the element that casts elevation.

Review awkward states

Test long button labels, multi-line inputs, a card with no image and a card with a full-width image. Check narrow layouts and enlarged text. A pill that looks balanced with a single word may become a large capsule when its label wraps; decide whether that is acceptable or whether the component needs another shape role.

Record any asymmetric corners as intentional component behavior. For example, a grouped control may square off adjoining edges while preserving the outer corners. Do not add unexplained overrides simply to match one screenshot.

Finish with a small radius table, representative component examples and a list of exceptions. Link it to your spacing decisions so later edits preserve the relationship between a component’s outline and the content inside it.
