Stabilize Table Columns with table-layout: fixed

Use fixed table layout with an explicit table width and intentional column sizes. Test long cell content without hiding values or losing table semantics.

By Penta AIPublished 17 November 20262 min read

In this guide

  1. Give the algorithm an explicit width
  2. Test values that challenge the column contract
  3. Preserve relationships while changing geometry

Fixed table layout calculates horizontal structure from the table width and column constraints rather than continually sizing columns around every cell’s content. It can make a predictable table easier to scan, but it does not make long values disappear safely or guarantee that every table fits a phone.

Give the algorithm an explicit width

<table class="assets">
  <caption>Example asset inventory</caption>
  <colgroup><col class="asset-name"><col></colgroup>
  <thead><tr><th scope="col">Name</th><th scope="col">Notes</th></tr></thead>
  <tbody><tr><td>navigation.svg</td><td>Primary navigation icon</td></tr></tbody>
</table>
.assets { width: 100%; table-layout: fixed; }
.assets .asset-name { width: 35%; }
.assets th, .assets td {
  padding: .75rem;
  text-align: start;
  vertical-align: top;
  overflow-wrap: anywhere;
}

The first column takes the specified share and the other receives remaining space in this two-column example. With an automatic table width, requesting fixed layout does not produce the same fixed-width behavior. Inspect the computed table width before changing cell declarations.

Reference: MDN table-layout.

Test values that challenge the column contract

Replace the short asset name with a long identifier, add a multiline note and insert more rows. The goal is stable column boundaries with understandable content. A wrapping policy can increase row height; that is often preferable to concealing information. Avoid assuming that fixed layout is also a truncation rule.

If the design requires ellipsis, provide an accessible way to reach the complete value. A tooltip that appears only on mouse hover is not enough. For a comparison table that genuinely needs more width, retain the table and use a deliberate scrolling region rather than squeezing each column into unreadable fragments.

Preserve relationships while changing geometry

  • Keep a caption and correctly associated headers.
  • Test a narrow container and enlarged text.
  • Check the longest identifier and translated column headings.
  • Verify copied and exported data retains complete values.

Use the responsive table guide for the surrounding overflow strategy. Use fixed layout when the column plan is known and useful; keep automatic layout when content-driven column sizing better serves the data. The choice should follow the reading task, not merely the first row’s appearance.
