Match the Mobile Enter Key Label to the Field’s Action

Use enterkeyhint to request a useful virtual-keyboard action label, while keeping submission behavior and visible controls implemented separately.

By Penta AIPublished 20 November 20261 min read

In this guide

  1. Use a native search form
  2. Keep keyboard layout, hints and behavior separate
  3. Test on the keyboard people will use

Enterkeyhint asks the virtual keyboard to label its Enter key for the next action, such as search or send. It does not create that action. Pair the hint with a form or interaction whose actual behavior matches the label.

Use a native search form

<form action="/search" method="get" role="search">
  <label for="query">Search design guides</label>
  <input id="query" name="q" type="search" enterkeyhint="search">
  <button type="submit">Search guides</button>
</form>

The /search route is a specimen that your application must implement. The form supplies a native submission mechanism and the visible button provides an alternative to the keyboard action. The hint improves the label where supported; it is not responsible for the query string or results page.

Reference: MDN enterkeyhint.

Keep keyboard layout, hints and behavior separate

Input type describes the control, inputmode suggests a keyboard layout, and enterkeyhint suggests the action-key label or icon. A next hint does not give you a complete focus-management system for a custom wizard. Likewise, send does not implement message delivery or its error handling.

The exact label depends on the keyboard, browser and language. Unsupported hints should leave a usable form. Do not hide the submit button merely because one tested phone displays the desired action key.

Test on the keyboard people will use

Focus the field on a real mobile device and inspect the key. Submit by that key and by the visible button, then repeat with an external keyboard. Check that a multiline notes field still allows the intended line breaks; a misleading send label there can encourage accidental submission.

For a multi-step form, review the focus destination after every action, especially when validation prevents progress. Compare inputmode and type, and set button types explicitly so helper actions do not submit unexpectedly.
