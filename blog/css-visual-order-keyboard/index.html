Check Keyboard Order After Reordering a CSS Layout

Audit flex and grid layouts whose visual order differs from the DOM. Compare keyboard movement, reading sequence and responsive rearrangements.

By Penta AIPublished 28 October 20262 min read

In this guide

  1. Reproduce the mismatch with two actions
  2. Choose the meaningful sequence first
  3. Review every responsive arrangement

Changing a component’s visual order with CSS does not automatically change its underlying reading and keyboard sequence. A row can look correct while focus appears to jump backward. Review the source order and the visible layout together, especially when a responsive design rearranges actions or form fields.

Reproduce the mismatch with two actions

<div class="example-actions">
  <button type="button">Review details</button>
  <button type="button">Continue</button>
</div>
.example-actions {
  display: flex;
  flex-direction: row-reverse;
  gap: 1rem;
}

In a left-to-right layout, these buttons appear in reverse visual order, while ordinary keyboard navigation follows their document order. Use the sample to observe the mismatch; it is not a recommended action arrangement. Repeat the inspection in any supported right-to-left layout because the inline start direction also changes.

Reference: MDN: ordering flex items and accessibility.

Choose the meaningful sequence first

Write the intended task sequence before adjusting the layout. If someone should review details before continuing, keep that relationship understandable in source and presentation. CSS grid placement and the order property can create similar differences, so the audit should not stop after removing row-reverse.

Do not patch a confusing layout with a series of positive tabindex values. Those values introduce a separate focus order that becomes difficult to maintain as controls are added, hidden or moved. Prefer a sensible document sequence and layout rules that preserve it.

Review every responsive arrangement

  • Tab through the controls at wide and narrow widths.
  • Check where Shift+Tab moves from the final action.
  • Read the content in document order, including any explanatory text.
  • Test dynamic states that insert errors or extra controls.

A purely decorative visual rearrangement may not change meaning, but a multi-step form or instruction sequence often does. Judge the actual task instead of declaring every use of order invalid. Capture the focus path with numbered notes when reporting an issue.

For handoff, include the intended reading order as well as the desktop and mobile compositions. The implementation should not require a reader to reconstruct the task from two competing sequences, one visible and one encountered through keyboard or assistive technology.
