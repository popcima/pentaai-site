Find the Cause Behind a Layout Shift

Trace a moving element back to the content that displaced it. Reproduce late images, banners and font changes, then verify a targeted layout-stability repair.

By Penta AIPublished 30 October 20262 min read

In this guide

  1. Record the moment and its context
  2. Reserve the space you actually know
  3. Follow the cause beyond images

The element that moves during a layout shift is not always the element that caused it. A paragraph may jump because an image, banner or newly inserted panel above it changed size. Start from a repeatable recording and trace the space change before applying a fixed height to the moving text.

Record the moment and its context

  • Open the page with consistent viewport and network conditions.
  • Record a load or the interaction that reveals the movement.
  • Inspect the layout-shift entry and its affected elements in browser performance tools.
  • Compare the frames immediately before and after the shift.

Record whether the issue occurs on initial load, after scrolling or during an interaction. A single clean reload does not rule out a shift that happens later. Keep the affected region, triggering event and suspected size change together in your notes.

Reference: web.dev: optimize Cumulative Layout Shift.

Reserve the space you actually know

<img src="/images/sample-panel.webp"
     width="1200" height="630"
     alt="A sample panel with its spacing annotations">
.article-figure img {
  max-inline-size: 100%;
  block-size: auto;
}

The asset path is illustrative. Dimensions must match the real image’s ratio so the browser can reserve useful space. If a responsive source changes composition and ratio, review that selection separately. Adding arbitrary dimensions can create a different mismatch when the media arrives.

Follow the cause beyond images

For a late banner, decide whether space should be reserved or whether the information belongs in an existing region. For a font change, compare the real and fallback metrics. For expanding user content, review whether the transition is expected and whether it displaces the current reading position.

  • Repeat the same recording after the targeted repair.
  • Check long content and narrower viewports.
  • Review later interactions rather than only the initial load.
  • Compare field evidence when available with controlled lab observations.

Do not hide a moving paragraph or lock it to a height that clips content just to improve one recording. A useful fix preserves the content and removes an avoidable surprise. Report the measured result with its test conditions; a screenshot of a stable frame is not evidence that the entire page has no layout shifts.
