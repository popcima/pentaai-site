Make New-Tab Links Predictable for Readers

Use new tabs only when needed, disclose the behavior in the link text, and keep opener behavior separate from the visible navigation experience.

By Penta AIPublished 21 November 20261 min read

In this guide

  1. Keep the notice part of the link
  2. Do not force every external link into another context
  3. Test the announcement and the return path

A link normally navigates in the current browsing context. When opening another tab or window serves a clear purpose, tell readers before activation. Target="_blank" requests a new browsing context; the browser and user settings decide its exact presentation.

Keep the notice part of the link

<a href="https://developer.mozilla.org/en-US/docs/Web/CSS"
   target="_blank" rel="noopener">
  CSS reference (opens in a new tab)
</a>

The destination is a real documentation page. The wording communicates the intended behavior without requiring a reader to recognize a small external-link icon. Rel="noopener" explicitly avoids giving the opened page an opener reference; modern browsers also provide implicit noopener behavior for ordinary _blank links.

Reference: MDN a.

Do not force every external link into another context

A documentation link is not automatically a reason to override familiar navigation. Consider whether the current page contains unsaved work or another concrete continuity need. Readers can often choose a new tab themselves through browser controls when the link retains normal behavior.

Opener handling and referrer handling are separate decisions. Do not add unrelated attributes just to copy a common snippet. If a project has a specific referrer policy, review that policy on its own terms.

Test the announcement and the return path

Inspect the link’s accessible name, activate it from the keyboard, and return to the original page. Make sure the notice is not duplicated by both hidden text and an icon label. If an icon is decorative, hide it from the accessibility tree while preserving the explicit wording.

Check narrow layouts so the notice wraps without separating it from the destination name. Use native links for navigation and the supporting-text guide when the interface needs a concise visible label with additional accessible context.
