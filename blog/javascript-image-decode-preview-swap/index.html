Decode a Replacement Image Before Swapping the Preview

Keep the previous preview while a new image decodes, handle failed requests, and guard against an older selection replacing a newer one.

By Penta AIPublished 22 November 20261 min read

In this guide

  1. Only the newest request may replace the preview
  2. Preserve layout and failure context
  3. Test rapid choices and a broken image

Image.decode returns a promise that resolves when image data is ready for use. For a preview switcher, decode the replacement before inserting it so the current preview can remain visible while loading. Also guard against an older request finishing after a newer choice.

Only the newest request may replace the preview

let previewVersion = 0;
async function updatePreview(src, alt) {
  const version = ++previewVersion;
  const image = new Image();
  image.alt = alt;
  image.src = src;
  try {
    await image.decode();
    if (version !== previewVersion) return;
    document.querySelector('#preview').replaceChildren(image);
    document.querySelector('#preview-status').textContent = 'Preview updated';
  } catch {
    if (version === previewVersion) {
      document.querySelector('#preview-status').textContent = 'Could not load the selected preview';
    }
  }
}

Provide the preview container, a suitable status region and real image URLs before calling this function. Pass alt text matching the selected image’s purpose. The version check suppresses stale completions; it does not cancel their network requests.

Reference: MDN decode.

Preserve layout and failure context

Reserve an appropriate preview area and style inserted images to fit it. Decoding alone does not prevent layout shifts from unexpected image dimensions. On failure, this specimen keeps the old preview visible and reports that the selected replacement did not load, so the retained image is not mistaken for a successful update.

A request failure, corrupt image or changed source can reject decoding. Do not swallow every rejection and then announce success. For responsive images, configure the relevant source selection before decoding the image you intend to insert.

Test rapid choices and a broken image

Choose two previews quickly while delaying the first response. Confirm that the first cannot overwrite the second. Request an invalid image and verify the old preview remains with a clear message. Check keyboard focus stays on the initiating control and that announcements do not repeat unnecessarily.

Use selected-source inspection and responsive-image setup when the displayed file differs from the one expected.
