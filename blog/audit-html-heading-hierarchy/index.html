Audit HTML Headings Without Changing the Design

Check heading levels, section relationships and reusable card titles. Repair the document outline while preserving the typography your design already uses.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Write the outline before changing tags
  2. Separate heading rank from type size
  3. Review the outline with real page states

Audit headings by reading their text and levels in document order, then comparing that outline with the page’s actual sections. A large bold paragraph is not a semantic heading. Conversely, a real heading can use restrained typography without losing its role.

Write the outline before changing tags

For a fictional export settings page, the outline could be: Export settings, File format, Image options, and Color profile. The first is the page title; File format and Image options are sibling sections; Color profile belongs inside Image options. This gives the section relationships a concrete meaning before CSS enters the discussion.

<h1>Export settings</h1>
<h2>File format</h2>
<!-- Format controls -->
<h2>Image options</h2>
<h3>Color profile</h3>
<!-- Profile controls -->

Use browser inspection to list the actual h1–h6 elements. Look for a section that jumps from h2 to h4, a card title marked up as a paragraph, or repeated navigation text that appears as a heading for no structural reason. Returning from h3 to h2 simply closes a subsection; that is different from skipping a level while opening one.

Reference: W3C WAI guidance on heading ranks.

Separate heading rank from type size

.page-title { font-size: clamp(2rem, 5vw, 3.5rem); }
.section-title { font-size: 1.5rem; }
.card-title { font-size: 1.125rem; }

Choose the element from the content hierarchy and the class from the visual role. If a reusable card appears under an h2 on one page and an h3 on another, let its component accept the appropriate heading level. Do not hard-code h4 just because the card title looks small.

A single clear main h1 is a useful convention for this page. Do not treat counting h1 elements as a complete audit, or claim that changing the count alone will improve rankings. The labels and nesting need to describe the content.

Review the outline with real page states

  • Read only the heading text: does it explain the page without the surrounding paragraphs?
  • Open optional sections and check headings inserted by the application.
  • Inspect desktop and mobile layouts for duplicated hidden headings.
  • Navigate by headings with a screen reader and confirm the sequence is useful.

Record the old tag, proposed tag and section relationship in the review. Keep visual adjustments separate so a semantic fix does not accidentally redesign the interface. For long section titles, review heading wrapping after the hierarchy is correct.
