Use CSS color-mix() for Related Surface Tokens

Derive a related interface surface with color-mix(). Choose the color space, keep a fallback and validate contrast instead of treating a mix as a guarantee.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Create one derived surface
  2. Name the color relationship
  3. Keep semantic roles explicit

color-mix() can express a relationship between a brand color and a surface color directly in CSS. That can make a token easier to maintain than a disconnected hex value. The relationship still needs visual and contrast review: mixing a fixed percentage of blue into white does not automatically produce an accessible text or control color.

Create one derived surface

:root {
  --brand: #245ec7;
  --canvas: #ffffff;
  --note-surface: #eef3fb;
}
@supports (color: color-mix(in oklab, black, white)) {
  :root {
    --note-surface: color-mix(in oklab, var(--brand) 10%, var(--canvas));
  }
}
.note { background: var(--note-surface); color: #17263f; }

The fallback is an independently chosen light surface, not a claim that it exactly equals the calculated mix. The supports condition matters because a custom property can hold an unsupported function as text; simply placing an older custom-property value before a newer one is not always a useful feature fallback.

Reference: MDN: color-mix().

Name the color relationship

The example mixes in Oklab and gives the brand a 10% contribution, with the remaining contribution assigned to the canvas color. Another color space can produce a different intermediate color. Record the space with the percentages so a later conversion to a static token does not silently change the result.

Mixing with transparent also affects alpha and therefore depends on the eventual background. Mixing with white produces a different relationship. If the same token is used over several surfaces, inspect the composed result in each location rather than comparing only a color picker’s raw value.

Keep semantic roles explicit

A note surface, a border and a text color have different requirements. Do not derive all three with one percentage because it keeps the token file short. Start with the surface relationship, then choose readable foreground and boundary treatments for the actual component.

  • Change the brand color to a much lighter and a much darker sample.
  • Review the component on each supported theme.
  • Measure contrast using the colors that are actually rendered together.
  • Check the fallback with the supports block disabled.

For handoff, include the semantic token name, its formula and the components that use it. When a theme changes the canvas token, repeat the review instead of assuming the original mixing percentage remains suitable. The formula communicates intent; it does not replace validation.
