Set a Touch Gesture Boundary Without Disabling Page Zoom

Use touch-action deliberately for a custom drag surface, preserve browser panning and pinch zoom, and check cancellation on a real touch device.

By Penta AIPublished 20 November 20261 min read

In this guide

  1. Scope the policy to the interactive surface
  2. Handle cancellation as part of the interaction
  3. Review the actual touch experience

Touch-action declares which gestures the browser may handle on a surface. It does not implement dragging. For a custom horizontal interaction inside a vertically scrolling page, pan-y pinch-zoom can preserve vertical browsing and zoom while leaving horizontal gesture handling to your code.

Scope the policy to the interactive surface

.horizontal-drag-surface {
  touch-action: pan-y pinch-zoom;
}
/* Ordinary page content keeps the browser default. */

Apply this only to an element whose horizontal pointer interaction already works. A normal horizontal overflow gallery may need native horizontal panning instead, so copying this declaration there can remove the very gesture readers expect. Start by deciding whether the browser or the application owns each direction.

Reference: MDN touch-action.

Handle cancellation as part of the interaction

When the browser takes over an allowed gesture, pointer handling may be canceled. Clear temporary drag state on pointercancel as well as on completion. The effective gesture policy also depends on relevant ancestors, so inspect the chain if a local declaration appears ineffective. Changing touch-action after a gesture starts does not rewrite that gesture’s policy.

A page-wide none is a poor shortcut for a local drag bug: it can suppress useful panning and zoom. Keep equivalent buttons or other keyboard actions for any operation that otherwise requires dragging.

Review the actual touch experience

On a touch device, begin a drag horizontally, vertically and diagonally. Pinch zoom over the component, then scroll from content beside it. Confirm cancellation leaves no stuck visual state and that controls remain usable after zooming. A desktop mouse test cannot establish these outcomes.

Use overscroll-behavior for scroll chaining, which is a separate concern, and retain clear button states for alternate actions.
