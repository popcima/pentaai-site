Base a Scripted Animation on Elapsed Time, Not Frame Count

Use the requestAnimationFrame timestamp for consistent duration, stop the loop at completion, and provide a reduced-motion path and cleanup function.

By Penta AIPublished 22 November 20261 min read

In this guide

  1. Run one bounded movement
  2. Define what happens while the page is hidden
  3. Review duration and interruption separately

Adding a fixed number of pixels on every animation frame ties speed to the display’s refresh rate. Calculate progress from the requestAnimationFrame timestamp instead, so a finite movement uses elapsed time rather than an assumed number of callbacks.

Run one bounded movement

function startSlide(dot) {
  if (matchMedia('(prefers-reduced-motion: reduce)').matches) {
    dot.style.transform = 'translateX(120px)';
    return () => {};
  }
  let start, frameId;
  function frame(now) {
    if (start === undefined) start = now;
    const progress = Math.min((now - start) / 800, 1);
    dot.style.transform = `translateX(${120 * progress}px)`;
    if (progress < 1) frameId = requestAnimationFrame(frame);
  }
  frameId = requestAnimationFrame(frame);
  return () => cancelAnimationFrame(frameId);
}

Call this with a real element inside a track large enough for the movement. Save the returned cleanup function and call it before removing the component or starting a replacement loop. The specimen travels 120px over 800ms of elapsed callback time and stops requesting frames at completion.

Reference: MDN requestAnimationFrame.

Define what happens while the page is hidden

Browsers commonly pause animation-frame callbacks in background tabs. When callbacks resume, the elapsed timestamp can jump forward. This formula advances to the corresponding progress, potentially finishing immediately. A timer-like experience that must pause while hidden needs a different, explicit elapsed-time policy.

The initial reduced-motion check avoids the movement in that state. If the animation is long-lived or restartable, also respond to preference changes rather than assuming the initial value remains permanent.

Review duration and interruption separately

Compare the movement on different refresh-rate displays where available. Interrupt it by removing the component, restart it and switch tabs during playback. Confirm there is only one active loop and that completion leaves a meaningful static state.

Use the motion review to decide whether movement is needed, and media-query change listeners to keep scripted behavior synchronized with preferences.
