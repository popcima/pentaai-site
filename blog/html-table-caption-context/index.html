Give a Data Table Its Own Caption and Scope

Use a table caption to identify the dataset and its scope, keep header relationships intact, and verify the table’s accessible name after styling changes.

By Penta AIPublished 23 November 20262 min read

In this guide

  1. Identify an explicitly illustrative inventory
  2. Keep a caption distinct from nearby headings
  3. Check the name and the reading path

A caption identifies the table it belongs to. It can make the dataset understandable when readers navigate directly to the table rather than reading the preceding paragraph. Write the caption around what the data represents, including the context needed to interpret it.

Identify an explicitly illustrative inventory

<table>
  <caption>Illustrative component inventory for a sample landing page</caption>
  <thead><tr><th scope="col">Component</th><th scope="col">Count</th></tr></thead>
  <tbody>
    <tr><th scope="row">Primary action</th><td>2</td></tr>
    <tr><th scope="row">Feature card</th><td>3</td></tr>
  </tbody>
</table>

The small dataset is invented for the example. The caption states its scope rather than implying a measured Penta AI result. Place the caption as the table’s first child; row and column headers still supply the relationships for individual values.

Reference: MDN HTML table caption context.

Keep a caption distinct from nearby headings

A section heading can introduce several tables or explain a broader subject. It is not automatically the caption of each table beneath it. Give each table enough context to be distinguished when encountered on its own, without repeating an entire preceding paragraph.

Caption-side can move the visible caption below a table without moving the element outside the table. Visual position and semantic association are separate. If the caption is hidden for a design reason, verify that the intended naming and visible context remain useful rather than assuming any hiding technique is harmless.

Check the name and the reading path

Inspect the table in the accessibility tree and confirm the expected caption contributes to its name or description under the chosen markup. Avoid adding competing ARIA labels without checking which text wins. Read a few cells with the supported assistive technology to verify headers as a separate concern.

Test a long caption on mobile and in print. Keep units, time period and any necessary data limitations available where readers need them. A good caption explains the dataset’s identity; it does not repair missing header associations or an unusable overflow layout.

Contain table overflow on small screens. Associate complex headers with cells.
