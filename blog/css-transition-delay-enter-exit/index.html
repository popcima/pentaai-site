Give Hover Entry and Exit Different Transition Delays

Place transition delays in the destination state, compare quick entry and exit, and avoid delaying the feedback that tells a user an action worked.

By Penta AIPublished 20 November 20261 min read

In this guide

  1. Delay only a decorative surface change
  2. Inspect interruption instead of assuming a full cycle
  3. Try quick passes and deliberate holds

A hover transition can wait before entering and return immediately on exit. Set the default delay to zero and the hovered state’s delay to the desired wait. The transition settings in the new state determine how that change begins.

Delay only a decorative surface change

.preview-card {
  background-color: #f4f6f8;
  transition-property: background-color;
  transition-duration: 180ms;
  transition-delay: 0ms;
}
.preview-card:hover {
  background-color: #e4f3eb;
  transition-delay: 250ms;
}
@media (prefers-reduced-motion: reduce) {
  .preview-card { transition: none; }
}

Entering hover uses the 250ms wait. Leaving restores the base delay, so the return can begin immediately. The example only changes decoration; it does not hide a panel or introduce a delayed action. Keep actual keyboard focus styling immediate and independent of the hover effect.

Reference: MDN transition-delay.

Inspect interruption instead of assuming a full cycle

A user may leave before the waiting period ends or reverse direction while the color is changing. Reversing transitions can use shortened timing, so do not calculate every interrupted sequence as a complete forward duration plus a complete backward duration.

For several properties, delay values follow the transition-property list. A short list repeats and an overlong list is truncated. Keep lists explicit when different effects need different schedules; otherwise a later edit can assign the wait to the wrong property.

Try quick passes and deliberate holds

Move the pointer across the card quickly, hold it, then leave halfway through the transition. Check keyboard focus, touch activation and reduced motion. If the delay makes a button appear unresponsive, remove it from the action feedback rather than adding a longer animation to compensate.

Use forced interaction states to inspect declarations and an explicit transition list to keep the effect bounded.
