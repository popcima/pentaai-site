How to Extract a Website Color Palette That You Can Use

Find a website’s colors in Chrome, separate CSS values from screenshot samples, and turn the result into a named palette with contrast checks.

By Penta AIPublished 25 October 20264 min read

In this guide

  1. Decide whether you need CSS values or sampled pixels
  2. Collect colors with Chrome CSS Overview
  3. Name colors by their jobs
  4. Check combinations, not individual swatches
  5. Export a small set of CSS variables
  6. Avoid the common extraction mistakes

To extract a website color palette, inspect the page’s CSS colors, group them by role, and record the foreground/background pairs used together. Chrome’s CSS Overview panel can help you collect page colors. Use the element inspector to confirm each important value before turning the collection into reusable variables.

A useful palette answers “which color goes where?” A long list of hex codes does not. This workflow produces a small palette for surfaces, text, borders, and actions, plus a record of the combinations that need checking.

Decide whether you need CSS values or sampled pixels

Use CSS inspection when you have access to a live page. Use an eyedropper when you are studying a screenshot, illustration, or visible composite. Keep those results labeled separately. Transparency, shadows, and gradients can make a sampled pixel differ from the underlying color declaration.

For example, white text at partial opacity over a dark panel has both a source color and a rendered appearance. Recording only the sampled gray loses the opacity rule. If the panel later changes, that flattened sample no longer describes the intended treatment.

Collect colors with Chrome CSS Overview

  1. Open the page in the theme and viewport you want to study.
  2. Open Chrome DevTools and its command menu.
  3. Search for Show CSS Overview and open that panel.
  4. Select Capture overview.
  5. Review the colors section, then inspect representative elements for the values you plan to keep.

Chrome’s CSS Overview documentation describes its page-level color and font summaries. Treat the capture as an inventory for that page, not proof that you have found every theme, state, or component on the site.

Capture again after opening a modal or switching a theme if those views matter. Record what changed. A green “success” message and a green brand button may share a value while serving different purposes.

Name colors by their jobs

Start with a small worksheet. The following palette is an original teaching example, not an extracted brand palette:

RoleExample valueWhere to inspect
Canvas#0B100CPage background
Surface#18221BCard or menu background
Text#F4F7F1Paragraph on canvas
Muted text#B7C1B9Secondary label on surface
Action#AEDFBBPrimary button
On action#102016Text inside that button

Do not merge colors solely because their hex values look close. First ask whether they represent the same role. Keep separate semantic names if two roles may need to change independently, even when their current values match.

Check combinations, not individual swatches

A color does not pass contrast on its own. Check the text against the surface it actually sits on. WCAG 2.2’s minimum text contrast criterion generally calls for at least 4.5:1, or 3:1 for large text, with defined exceptions. Read the W3C explanation and large-text definition when applying those thresholds.

Chrome’s Color Picker reference describes its contrast controls. Check which contrast model your tool displays; an APCA result is not a WCAG 2.x ratio. For gradients or photographs, examine the backgrounds behind the text across its occupied area.

Keep a matrix of actual combinations: text on canvas, muted text on surface, button text on action, and focus indicator against adjacent colors. Do not label the whole interface accessible after checking only one button.

Export a small set of CSS variables

Here is a reusable starting point for the example palette. It deliberately uses role names so you can change the visual direction without rewriting every component:

:root {
  --canvas: #0b100c;
  --surface: #18221b;
  --text: #f4f7f1;
  --text-muted: #b7c1b9;
  --action: #aedfbb;
  --on-action: #102016;
}
.card { background: var(--surface); color: var(--text); }
.button { background: var(--action); color: var(--on-action); }

Download the example palette CSS or follow the Tailwind token mapping guide to use named values in utility classes.

Avoid the common extraction mistakes

  • Saving only a screenshot: retain CSS values and their roles when you can inspect them.
  • Flattening transparency: record alpha and the background behind it.
  • Ignoring states: inspect hover, focus, selected, and error states that belong in your design.
  • Collecting photo colors as UI tokens: keep editorial imagery separate from interface colors.
  • Copying without a purpose: choose a palette suited to your content and verify your own combinations.

Pair the palette with a typography audit, then place both in the wider design-system inventory. Your final file should tell a builder how to use each color and which combinations still require review.
