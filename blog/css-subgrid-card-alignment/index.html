Align Card Titles and Footers with CSS Subgrid

Use row subgrid to align card sections across a collection without fixed text heights. Build a fallback and test long titles, missing content and narrow layouts.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Give every card the same section structure
  2. Stress the alignment with content
  3. Decide whether coordination is actually wanted

Use row subgrid when neighboring cards should share the same title, body and footer tracks. Independent nested grids cannot coordinate those interior row sizes. A fixed heading height may appear to solve the problem until a longer title or larger text arrives. Subgrid lets the parent grid coordinate the rows while each card keeps its own markup.

Give every card the same section structure

<div class="cards">
  <article class="card">
    <h2>Short title</h2>
    <p>A concise description.</p>
    <a href="/guide-a/">Read guide A</a>
  </article>
  <article class="card">
    <h2>A longer title that wraps onto another line</h2>
    <p>Another description.</p>
    <a href="/guide-b/">Read guide B</a>
  </article>
</div>
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 18rem), 1fr));
  gap: 1.25rem;
}
.card { display: grid; gap: 1rem; padding: 1.25rem; }
.card > * { margin: 0; }
@supports (grid-template-rows: subgrid) {
  .card { grid-row: span 3; grid-template-rows: subgrid; }
}

The baseline is an ordinary readable card grid. The enhancement makes each card span three parent rows and reuse those tracks internally. The example links are placeholders for your actual routes. Use real destinations when adapting the markup.

MDN’s subgrid guide explains track sharing and inherited gaps. Only the selected axis becomes a subgrid here: the cards share rows, while the parent still decides how many card columns fit.

Stress the alignment with content

Compare a one-line title with a three-line title in the same visual row of cards. Their body sections should begin on the shared next track. Then add a long description and inspect where the footers land. This reveals the actual benefit more clearly than three cards with identical placeholder text.

Keep the three-section contract explicit. If an image becomes a fourth direct child, update the track span and placement strategy. If a description is optional, preserve an intentional slot or define explicit grid placement; silently removing a child can shift the footer into the wrong row. Avoid empty filler text just to force an alignment.

CaseExpected review
Two cards with different title lengthsBody sections begin on the same shared track.
One card at a narrow widthContent reads in its original order.
Description omittedFooter remains in its intended section.
Larger textRows grow without clipped copy.

Decide whether coordination is actually wanted

Shared tracks trade compactness for alignment. A long description can create space in its neighboring card, which may be desirable in a comparison grid and unnecessary in a news feed. Check real content before applying subgrid to every card on the site.

Finish by documenting the section count, fallback behavior and expected alignment at each layout. Keep DOM order logical and let the grid handle presentation. This gives the next developer a concrete contract to maintain when adding badges, metadata or a second action.
