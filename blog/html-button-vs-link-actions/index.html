Button or Link? Choose by What Activation Does

Choose an anchor for navigation and a button for actions. Inspect keyboard behavior, real URLs and component APIs without changing the visual design.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Classify the behavior before the style
  2. Remove placeholder navigation
  3. Test the element’s expected interaction

Use an anchor with a real href when activation takes the reader to a destination. Use a button when activation performs an action in the current interface. The shape, color or prominence of the control does not determine its HTML element.

Classify the behavior before the style

<a class="primary-action" href="/exports/">View exports</a>
<button class="primary-action" type="button" id="preview">
  Refresh preview
</button>

The first example has a destination that can be copied or opened in another tab. The second asks the application to do work. A shared CSS class can make both look like the same design-system control while preserving their different semantics. The example button still needs an application handler; its label alone does not implement a refresh.

Reference: MDN anchor element reference.

A download link to an existing file can also be an anchor. A control that first generates a report may be an action button, followed by a link when the file becomes available. Describe those two steps in the component specification instead of choosing an element from the word “Download” alone.

Remove placeholder navigation

An anchor with href="#" is not a good substitute for a button. It exposes a navigation target even when the intended behavior is opening a menu or copying text. Removing href also removes the normal link behavior rather than turning the anchor into a native button.

For a client-side router, preserve a real destination href and review modified clicks, browser history and loading failures. JavaScript can enhance navigation without requiring every destination to become a click handler on a generic element. Avoid placing one interactive control inside another, such as a delete button inside a fully linked card.

Test the element’s expected interaction

  • Tab to the control and check its accessible name and role.
  • Activate links with Enter and test copying or opening their destinations.
  • Activate native buttons with Enter and Space, checking that the action runs once.
  • Confirm action buttons inside forms have an intentional type.
  • Check visible focus, long labels and any resulting focus movement.

During handoff, include a behavior column beside each control: destination URL or action, loading state, and result. Review button states separately once the underlying element is correct. A screenshot can show the visual hierarchy, but it cannot establish whether the control has the right browser behavior.
