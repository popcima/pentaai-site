Mark Up Dates with HTML time and datetime

Separate readable date labels from machine-readable values. Choose date-only or timestamp formats and check that timezones, metadata and visible text agree.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Represent the kind of date you actually have
  2. Use one source of truth for visible and hidden values
  3. Inspect dates as content, not decoration

Use a time element with a valid datetime value when a visible date needs an unambiguous machine-readable representation. Keep a calendar date distinct from a timestamp: an article publication day and a meeting’s exact start time do not require the same information.

Represent the kind of date you actually have

<p>Published <time datetime="2026-11-14">November 14, 2026</time></p>
<p>Review starts <time datetime="2026-11-14T15:00:00-05:00">
  November 14 at 3:00 p.m. Eastern Standard Time
</time>.</p>

The first example is a date without an invented hour or timezone. The second is an illustrative timestamp with an explicit offset. Its human-readable label must describe the same instant. An offset records the relationship to UTC for that timestamp; it is not a complete rule for scheduling recurring events across daylight-saving changes.

Reference: MDN time element and accepted datetime formats.

Use one source of truth for visible and hidden values

A templating bug can show November 14 while leaving November 13 in datetime or structured data. Generate those representations from the same validated content field. If a page displays a localized time, format the label and timestamp from the same instant instead of splicing together unrelated strings.

Do not automatically convert a date-only publication value to local midnight in every visitor’s timezone. That transformation can shift the displayed calendar day. Define whether the field represents a calendar date or an instant before passing it through a date library.

The time element does not create a date picker, timezone selector or automatic calendar invitation. It also does not prove that an article was updated. Preserve an original publication date and expose a modified date only when there is a substantive update worth representing.

Inspect dates as content, not decoration

  • Compare visible text, datetime, structured data and any feed values.
  • Test an event near midnight in more than one timezone.
  • Check month and day ordering in the intended locale.
  • Include the year when an old entry could otherwise be ambiguous.
  • Verify that labels such as Published and Updated mean what the data says.

For a US-facing interface, a label such as “November 14, 2026” avoids the ambiguity of a numeric date. In a dense activity table, combine explicit labels with tabular numerals when appropriate. Typography can improve scanning, but the underlying time semantics still need to be correct.
