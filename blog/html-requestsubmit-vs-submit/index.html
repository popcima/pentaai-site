Submit a Form from JavaScript Without Skipping Validation

Compare requestSubmit with submit when JavaScript starts a form action. Preserve native validation, submit events and the intended submit button’s behavior.

By Penta AIPublished 18 November 20261 min read

In this guide

  1. Name the intended submit button
  2. Preserve the event contract
  3. Test each initiation path

Use requestSubmit() when JavaScript should initiate the normal form-submission path, including validation and a submit event. Calling submit() directly bypasses those two steps. That difference explains why the same form can reject an empty field with a button but send it through a script.

Name the intended submit button

<form id="review">
  <label for="review-title">Review title</label>
  <input id="review-title" name="title" required>
  <button id="save-review" type="submit" name="action" value="save">
    Save review
  </button>
</form>
const form = document.querySelector('#review');
const save = document.querySelector('#save-review');
// Call in response to the intended application action:
form.requestSubmit(save);

Run this in a controlled fixture before connecting a real endpoint. Leave the title empty, then fill it and repeat. A supplied submitter must be a submit button associated with that form. Passing a different element or a button belonging to another form is not a valid shortcut.

Reference: MDN requestSubmit.

Preserve the event contract

A submit handler can prevent navigation and implement an asynchronous request, but it should not call requestSubmit again unconditionally: that can re-enter its own event path. Decide where the application transitions from native validation to custom transport, and keep that transition explicit.

Direct submit does not fire the submit event and does not perform constraint validation. It is therefore unsuitable when your logic depends on that handler or on the browser checking required fields. A control named submit can also mask the form’s submit method, making a seemingly ordinary method call fail.

Reference: MDN submit method differences.

Test each initiation path

  • Activate the native button with pointer and keyboard.
  • Initiate the programmatic path with invalid and valid values.
  • Confirm the expected submitter and action value.
  • Verify the server independently validates the request.

Use the submitter guide when the form has more than one action. Native client validation improves interaction; it does not replace server validation or authorization.
