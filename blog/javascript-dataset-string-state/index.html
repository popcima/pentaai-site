Read Data Attributes as Strings When Inspecting State

Parse data attribute values explicitly, understand dash-to-camelCase names, and avoid treating the string false as a Boolean false in component logic.

By Penta AIPublished 22 November 20261 min read

In this guide

  1. Parse the value you actually expect
  2. Distinguish missing values from serialized values
  3. Test unexpected input representations

Dataset exposes data-* values as strings. A component with data-expanded="false" does not give JavaScript a Boolean false; it gives a nonempty string. A truthiness check can therefore reverse the state you meant to inspect.

Parse the value you actually expect

<div id="review-panel" data-expanded="false" data-item-count="3"></div>
<script>
const panel = document.querySelector('#review-panel');
const expanded = panel.dataset.expanded === 'true';
const count = Number(panel.dataset.itemCount);
console.log(expanded); // false
console.log(count); // 3
</script>

The HTML name data-item-count becomes dataset.itemCount. The strict comparison defines the accepted true representation. Numeric conversion still needs validation if the value may be missing, empty or malformed; Number alone is not a complete data contract.

Reference: MDN dataset.

Distinguish missing values from serialized values

Assigning to a dataset property writes a string representation back to the attribute. Assigning false produces "false" rather than removing the attribute. Use delete panel.dataset.expanded when the attribute should be absent, and decide whether absence means default, unknown or another explicit state.

Custom data attributes do not automatically communicate an expanded or pressed state to assistive technology. Keep native behavior or the appropriate ARIA state synchronized through the application’s actual state model instead of using data attributes as a substitute.

Test unexpected input representations

Inspect false, true, an empty attribute and a missing attribute. Try a malformed numeric count and check that the interface does not display NaN or silently accept it. If both CSS and JavaScript read the state, document the exact allowed strings so the selectors and logic agree.
