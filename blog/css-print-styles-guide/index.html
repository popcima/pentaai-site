CSS Print Styles: Make Guides Readable on Paper and PDF

Create a focused print stylesheet for article pages. Remove repeated chrome, preserve meaningful content and inspect page breaks, code blocks and table overflow.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Start with explicit print overrides
  2. Keep the useful information visible
  3. Use print preview as the acceptance check

A page designed for a screen can waste paper or hide information when printed. Build a print view around the content someone wants to keep: title, explanation, examples and references. Remove repeated navigation where appropriate, but preserve content that the reader needs after the browser is gone.

Start with explicit print overrides

@media print {
  .site-nav, .newsletter-form, .floating-toolbar { display: none; }
  body { color: #000; background: #fff; }
  main { width: auto; max-width: none; margin: 0; }
  .sticky-summary { position: static; }
  pre { white-space: pre-wrap; overflow-wrap: anywhere; }
  h2, h3 { break-after: avoid; }
  figure { break-inside: avoid; }
}
@page { margin: 18mm; }

Use selectors that exist in your project. The margin is an example to preview with your expected paper sizes. Avoid a universal rule that prevents every element from breaking across pages; a large section still needs to flow, and an image taller than a page cannot remain intact simply because CSS asks it to.

MDN’s printing guide explains print media styles and page rules. Normal cascade precedence still applies, so check which declaration wins when a screen rule seems to survive your print stylesheet.

Keep the useful information visible

Open every disclosure or alternate tab that contains essential printable content, or provide a deliberate print representation of that information. Do not assume a closed panel will be printed just because its data exists somewhere in the application. Test the output rather than relying on the screen DOM alone.

Inspect tables and code blocks carefully. A scrollable region can hide offscreen content in print. A wide comparison table may need a simpler print layout or a dedicated export. Wrapping code can help, but check that long lines and indentation remain understandable. Never silently drop columns that are required to interpret a result.

Use print preview as the acceptance check

Preview itemQuestion
First pageAre title and context present?
Page boundariesAre headings stranded without their following text?
FiguresAre meaningful labels readable?
Tables and codeIs any content clipped off the paper?
LinksCan the printed reader identify important references?

If you append URLs to printed links, target references deliberately. A global a::after rule can print navigation fragments, long query strings and duplicate addresses everywhere. For a technical guide, a short source list may be easier to read than expanding every inline link.

Preview both Letter and A4 if your audience uses both. Check with background graphics disabled, because print settings may omit them. A white label on a background that disappears can become unreadable. Save a PDF from the actual browser print flow and inspect its last page as well as its first. Media emulation is useful during development, but pagination needs its own review.
