How to Find and Fix Horizontal Overflow on Mobile

Track down the element making a page wider than its viewport. Fix grid minimums, long content, media and fixed widths without hiding useful content.

By Penta AIPublished 26 October 20263 min read

In this guide

  1. Record the failing conditions
  2. Work from the widest box inward
  3. Fix common constraints at their source
  4. Test content that stresses the layout
  5. Confirm the repair survives the full page

To fix horizontal overflow, identify the box that exceeds its available width and correct that constraint. Hiding overflow on the entire page can conceal the symptom while leaving content, focus outlines or controls inaccessible. Start with the narrowest width that reproduces the problem.

Separate accidental page scrolling from intentional scrolling inside a code example or data table. A wide table may need its own scroll container. A paragraph or ordinary navigation bar generally should not push the whole document sideways.

Record the failing conditions

Use Chrome’s responsive viewport controls and change width gradually. Note the first width at which a horizontal scrollbar appears, the current page state, and whether a menu or dialog is open. Device mode approximates a mobile environment; verify the final behavior on a real device when possible.

Compare the problematic page with a simpler page that shares the same header. If both fail, inspect the shared shell first. If only a product page fails, examine its unique images, specifications and long names. This quick comparison reduces the number of containers you need to inspect.

Work from the widest box inward

Likely causeFocused repair
Fixed width exceeds the containerAdd an appropriate maximum width or responsive constraint
Flex or grid item refuses to shrinkInspect its automatic minimum size
Long unbroken URLAllow wrapping in the text region
Large image or videoConstrain media to its content container
Table or code blockProvide a deliberate local scrolling area

Use element highlights and the box-model panel to locate the edge extending beyond the viewport. Check padding and borders as well as the declared width. Also inspect absolute positioning and transforms: visual movement can create overflow even when the normal layout width seems reasonable.

Fix common constraints at their source

.layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr);
}
.main, .card { min-width: 0; }
.article img, .article video {
  max-width: 100%;
  height: auto;
}
.long-link { overflow-wrap: anywhere; }
.code-scroll { max-width: 100%; overflow-x: auto; }

Apply each rule where its purpose fits. min-width: 0 allows a flex or grid item to shrink below an automatic content-based minimum; it does not magically wrap everything inside that item. MDN explains the automatic sizing behavior in its min-width reference.

If a two-column grid contains a sidebar and a wide article, use a track such as minmax(0, 1fr) for the flexible content and confirm that the sidebar also fits. On sufficiently narrow screens, the layout may need one column. Do not reduce text to an unreadable size merely to preserve the desktop arrangement.

Test content that stresses the layout

Replace a sample title with a long real title. Test an unbroken address, a large image, a multi-column table and enlarged text. Open the mobile menu and move keyboard focus through every item. A clipping fix that makes the screenshot look cleaner can still hide the currently focused control.

WCAG’s reflow guidance explains the goal of reading content without unnecessary scrolling in two dimensions, with exceptions for content whose meaning requires a two-dimensional layout. Use that distinction when deciding whether a local table scrollbar is appropriate.

Confirm the repair survives the full page

Reload after saving the source change, retest the original failing width and check widths on either side. Then inspect another page using the repaired component. Record the responsible selector and the content that exposed it so the next regression is reproducible.

A useful fix often removes one inappropriate width or minimum rather than adding many breakpoints. Once the page fits, return to spacing and typography; those decisions should improve readability within a working layout, not disguise an unresolved sizing constraint.
