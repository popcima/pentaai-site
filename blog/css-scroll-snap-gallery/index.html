Build a Scroll-Snap Gallery That Still Scrolls Naturally

Create a horizontal card gallery with CSS scroll snap. Set the container and item roles, preserve keyboard access and choose proximity snapping deliberately.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Use a named scroll region
  2. Check both the container and its children
  3. Review the whole interaction

CSS scroll snap can help a horizontal gallery settle near a card edge without replacing native scrolling. Put the snap policy on the scroll container and the alignment on its children. Start with proximity snapping for a reading-oriented gallery, then test whether stronger snapping actually helps the task.

Use a named scroll region

<section aria-labelledby="samples-title">
  <h2 id="samples-title">Layout samples</h2>
  <div class="samples" tabindex="0" role="region"
       aria-label="Scrollable layout samples">
    <article class="sample"><h3>Editorial</h3><p>Sample notes.</p></article>
    <article class="sample"><h3>Catalog</h3><p>Sample notes.</p></article>
    <article class="sample"><h3>Dashboard</h3><p>Sample notes.</p></article>
  </div>
</section>
.samples {
  display: flex;
  gap: 1rem;
  overflow-x: auto;
  scroll-snap-type: x proximity;
  scroll-padding-inline: 1rem;
  padding: 1rem;
}
.sample { flex: 0 0 min(85%, 22rem); scroll-snap-align: start; }
.samples:focus-visible { outline: 3px solid #174fa0; outline-offset: 2px; }

The next card can peek into view, providing a cue that more content is available. Keep a scrollbar or another clear cue rather than assuming users will discover a horizontal gesture. The focusable region supports keyboard testing; avoid unnecessary extra tab stops in galleries that already have a better keyboard interaction model.

Reference: MDN: scroll-snap-type.

Check both the container and its children

If nothing snaps, confirm that the region actually overflows and that the children have snap alignment. A flex row whose cards shrink to fit may never become scrollable. If it feels too aggressive, compare proximity with mandatory using long cards and a small viewport. Snapping should not make content hard to inspect between preferred positions.

Review the whole interaction

Tab into the region, use the available keyboard scrolling controls, then Tab onward. Check that focus remains visible and that links inside later cards can be reached. Try touch, trackpad and a mouse with horizontal scrolling. Increase text size so each card becomes taller and review whether the surrounding page still scrolls comfortably.

Do not automatically add looping, autoplay or smooth scripted movement. Those are separate product decisions with additional controls and motion considerations. For a simple set of examples, native scrolling plus a clear alignment policy may be enough. Record the card width, gap, snap alignment and input methods checked in the handoff.
