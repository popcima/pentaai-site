Keep Scripted Behavior in Sync with a Media Query

Read a media query at startup, listen for match changes, and remove listeners when a component is destroyed so scripted behavior stays synchronized.

By Penta AIPublished 20 November 20261 min read

In this guide

  1. Initialize before listening
  2. Choose the correct source of truth
  3. Test crossing the boundary both ways

Use matchMedia when JavaScript needs the answer to a CSS media query. Read matches immediately, then subscribe to change. A listener alone misses the initial state; a one-time read misses a later viewport or preference change.

Initialize before listening

const compact = matchMedia('(max-width: 48rem)');
const panel = document.querySelector('.review-panel');
function syncLayout() {
  if (panel) panel.dataset.layout = compact.matches ? 'compact' : 'wide';
}
syncLayout();
compact.addEventListener('change', syncLayout);
// When this component is permanently removed:
// compact.removeEventListener('change', syncLayout);

This example exposes the current match as a data attribute. It does not hide controls or move focus. The change event reports a change in the query result, rather than every pixel of resizing. Keep the function reference so teardown can remove the same listener.

Reference: MDN matchMedia.

Choose the correct source of truth

A viewport query is not a measurement of the panel itself. A narrow sidebar can hold a compact component even on a wide screen; use CSS container queries for that styling problem. Prefer CSS alone when the only effect is visual. Duplicate breakpoint logic in JavaScript and CSS creates a maintenance obligation.

For a scripted animation, the query can instead check prefers-reduced-motion. Apply the initial preference before starting motion and update the animation system when it changes.

Test crossing the boundary both ways

Open below the breakpoint, enlarge the viewport, then shrink it again. Confirm the initial state and both transitions. Mount and remove the component repeatedly to check for duplicate callbacks. Keep typed values, active selections and keyboard focus intact throughout the change.

See the reduced-motion review for motion decisions and container-query guide for component-driven styling.
