Diagnose a Canvas Export Blocked by an Image’s Origin

Check cross-origin image request mode and server permission before canvas export, distinguish decode failures from tainted pixels, and preserve a clear failure state.

By Penta AIPublished 24 November 20262 min read

In this guide

  1. Request an image with the intended CORS mode
  2. Distinguish loading failure from a tainted canvas
  3. Test the export path and its failure message

An image can display in a page while its pixels cannot be read back from a canvas. Drawing a cross-origin image without the required permission can make the canvas non-origin-clean, causing export or pixel-reading operations to fail. Display success alone is not export permission.

Request an image with the intended CORS mode

async function exportPreview(src) {
  const image = new Image();
  image.crossOrigin = 'anonymous';
  image.src = src;
  await image.decode();
  const canvas = document.createElement('canvas');
  canvas.width = image.naturalWidth;
  canvas.height = image.naturalHeight;
  canvas.getContext('2d').drawImage(image, 0, 0);
  return canvas.toDataURL('image/png');
}

Call this with an image you are authorized to use and handle rejection in the caller. For a foreign origin, the image server must supply an appropriate CORS response. Setting crossOrigin before src configures the request; it cannot grant permission that the server does not provide.

Reference: MDN canvas cross origin image export.

Distinguish loading failure from a tainted canvas

A CORS-mode request can fail to load when the server does not allow it. A different request made without that mode may display and draw, but then prevent reading the resulting pixels. Inspect the Network response and the point where the operation fails instead of treating both cases as a broken PNG encoder.

Use a same-origin asset or a source whose owner provides the required access. Do not disable browser security or route unapproved assets through a proxy merely to evade the restriction.

Test the export path and its failure message

Compare a same-origin image, an allowed cross-origin image and a denied one in a controlled test. Check that a failed replacement does not overwrite a valid preview or announce a successful export. Bound image dimensions in production so unexpectedly large sources do not create excessive canvas memory use.

The returned data URL is only a small-example export format. A production workflow may prefer a Blob and an explicit download lifecycle; origin restrictions still apply.

Handle image loading failures and stale choices. Inspect the actual selected source.
