text-wrap: balance vs pretty for Headings and Copy

Compare balanced headings with improved paragraph wrapping. Apply text-wrap selectively and test real fonts, narrow widths and changing content.

By Penta AIPublished 27 October 20262 min read

In this guide

  1. Start with a stable text measure
  2. Choose the property for the content
  3. Review the states that alter line breaks

Use text-wrap: balance to improve the distribution of a short heading across lines. Consider text-wrap: pretty for selected reading text where the browser can favor a better line arrangement. Neither value replaces a sensible text width, font size or content edit, and exact line breaks can vary by browser and font.

Start with a stable text measure

.feature-heading {
  max-inline-size: 20ch;
  text-wrap: balance;
}
.feature-intro {
  max-inline-size: 60ch;
  text-wrap: pretty;
}

Try the heading “Inspect the details behind a better interface” with your actual typeface. Compare the default wrapping and balanced wrapping at several widths. A 20ch measure is an illustrative starting point, not a universal headline width; ch itself depends on the selected font’s metrics.

Reference: MDN: text-wrap.

Choose the property for the content

Balancing is intended for short blocks, and browsers limit how many lines they balance. Pretty wrapping gives the browser room to improve the layout of text, but its precise algorithm and support can differ. Apply these as progressive enhancements: the copy should remain readable with ordinary wrapping.

Do not insert hard line breaks solely to reproduce a desktop screenshot if the same heading must adapt to mobile widths. A forced break can make a narrow layout worse. Keep intentional breaks for cases where the content or design genuinely requires them and test those separately.

Review the states that alter line breaks

  • Check before and after the web font loads.
  • Use the shortest and longest real heading examples.
  • Test narrow cards as well as full-width sections.
  • Zoom text and inspect the heading’s relationship to nearby controls.

If the last word still looks stranded, first inspect the text measure and wording. Adding balance to a container with a fixed height may reveal a different problem: the heading can gain a line and collide with the next element. Let content determine block height instead of relying on the original line count.

For long bodies of text, evaluate the tradeoff before applying pretty everywhere. Use it where the typographic benefit is visible and the page remains responsive with realistic content. A page full of short UI labels does not need the same treatment as an editorial introduction.

In design handoff, specify the maximum measure and wrapping preference without requiring one exact set of line endings on every device. That gives the implementation room to respect reader settings while keeping the intended hierarchy.
