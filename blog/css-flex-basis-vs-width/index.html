Why a Flex Item Ignores Its Declared Width

Trace a flex item’s starting size through flex-basis, width, growth and shrinkage. Use a controlled layout to distinguish a basis from the final width.

By Penta AIPublished 17 November 20262 min read

In this guide

  1. Start with a case that cannot grow or shrink
  2. Reintroduce the constraints deliberately
  3. Write down the intended sizing contract

In a horizontal flex row, a definite flex-basis supplies the starting main size in preference to width. That starting size is still subject to growth, shrinkage and minimum-size constraints. Comparing only the width declaration with the final box skips the algorithm that runs between them.

Start with a case that cannot grow or shrink

.row { display: flex; gap: 1rem; }
.sample {
  box-sizing: border-box;
  width: 18rem;
  flex: 0 0 12rem;
}

In a sufficiently wide row with no conflicting minimum or maximum, the sample starts and stays at a 12rem border-box width. Switch its basis to auto and the declared 18rem width becomes relevant to the starting size. Change one property at a time and measure the item’s border box in DevTools.

Reference: MDN flex-basis.

Reintroduce the constraints deliberately

Now set flex: 1 1 12rem. Extra room can enlarge the item and insufficient room can shrink it. The 12rem basis is no longer a promised final width. Add a second item and compare short content with an unbroken identifier; an automatic minimum can prevent the shrinkage you expected.

Check the main axis as well. With column direction, flex-basis participates in height sizing rather than serving as another width control. Percentage bases also need a definite main size to resolve as expected; an indefinite container can produce content-based behavior. Record the container’s sizing context before copying a percentage between layouts.

Write down the intended sizing contract

  • For an inflexible item, specify its basis and whether overflow is acceptable.
  • For a flexible item, decide how surplus and deficit space should be shared.
  • Inspect minimums and maximums before adding important declarations.
  • Verify padding and borders under the chosen box-sizing model.

If the purpose is equal flexible cards, test unequal content instead of using three identical placeholders. If one control must remain legible beside shrinking text, use the button shrinkage guide to assign the constraint to the correct item. The useful handoff states which part may change size, not merely the width observed in one screenshot.
