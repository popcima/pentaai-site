Test a Page with User Text-Spacing Overrides

Review text after line, paragraph, letter and word spacing increase together. Find clipping and lost controls without redesigning the site around one preset.

By Penta AIPublished 16 November 20262 min read

In this guide

  1. Use the four spacing relationships
  2. Inspect the components most likely to lose content
  3. Save evidence and restore the normal page

Test text-spacing adaptability by applying the relevant spacing changes together and checking that content and controls remain usable. This is an override test, not a requirement that the site’s default typography use those values. Preserve the page’s ordinary font size and other styles during the focused check.

Use the four spacing relationships

Line height: at least 1.5 × font size
Space after paragraphs: at least 2 × font size
Letter spacing: at least 0.12 × font size
Word spacing: at least 0.16 × font size

These are the relationships used by WCAG’s text-spacing criterion for applicable markup and scripts. Apply them through a review stylesheet or an appropriate testing tool, taking care not to reduce a value that is already larger. The language/script exception matters when a spacing property is not used by that writing system.

Reference: W3C Text Spacing explanation.

Inspect the components most likely to lose content

Start with short fixed-height controls, navigation labels, notification banners and dense cards. Increased spacing can make a label wrap into a height that the original specimen never required. Look for text clipped by overflow, buttons whose second line is covered and content colliding with an icon.

Read an entire paragraph, not only its first line. Check the boundary between paragraphs and the next component. A fixed card height can preserve a neat grid while silently losing the end of the text. A multiline clamp may also need review when the shortened preview stops conveying useful information.

When you find a failure, disable the particular height or clipping constraint in DevTools to identify the cause. Do not “repair” the test by overriding the user’s spacing back to your preferred values. The goal is an adaptable component.

Save evidence and restore the normal page

  • Record the override values and the affected content.
  • Test links, form submission and disclosure controls after wrapping changes.
  • Repeat with long labels and realistic paragraph lengths.
  • Verify any intentional truncation still has a usable route to the full content.
  • Remove the diagnostic override before reviewing the normal visual design.

This focused check does not establish complete accessibility conformance. It gives a reproducible way to find one class of layout failure. Keep the defect report tied to lost content or functionality and review the line-height inheritance guide if nested text behaves inconsistently.
