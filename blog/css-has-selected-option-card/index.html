Style a Selected Option Card with CSS :has()

Let a labeled checkbox drive its card’s selected appearance with :has(). Keep native interaction, a usable fallback and a selector scoped to the component.

By Penta AIPublished 30 October 20261 min read

In this guide

  1. Let the control own the state
  2. Keep the relationship explicit
  3. Test interaction before polishing the border

The :has() selector can style a card according to a checked input inside it. This avoids a separate selected class that can drift out of sync with the real control. Keep the checkbox visible and labeled so the selected state remains understandable when the optional card styling is unavailable.

Let the control own the state

<label class="option-card">
  <input type="checkbox" name="include-notes">
  <span>Include review notes</span>
</label>
.option-card {
  display: flex; gap: .75rem; padding: 1rem;
  border: 2px solid #9aa6b6; border-radius: .75rem;
}
.option-card:has(> input:checked) {
  border-color: #174fa0; background: #e7f0ff;
}

Clicking the wrapping label toggles the checkbox without custom click handlers. The checked state remains the source of truth. This example is a form option; it does not implement a navigation card or submit anything by itself.

Reference: MDN: :has() relational pseudo-class.

Keep the relationship explicit

The direct-child combinator limits the condition to the input belonging to this card. A broad descendant selector can accidentally react to a nested component. Scope the rule to a small component instead of repeatedly asking whether the entire document contains a changing state.

The selector’s specificity depends on its arguments, so adding an ID inside :has() can unexpectedly make the rule harder to override. Keep the arguments as simple as the relationship allows. Do not nest :has() inside another :has().

Test interaction before polishing the border

  • Toggle the option with Space while the checkbox has keyboard focus.
  • Click the label text and the card’s padded region.
  • Disable the :has() rule and confirm the option still works.
  • Review checked, unchecked, disabled and focus states on the real surface.

Preserve a visible focus indicator on the input or a deliberate equivalent for its card. The border change is a supplemental state cue, not a substitute for the native checked control. When multiple choices are mutually exclusive, use a properly labeled radio group rather than coordinating several checkboxes through CSS.
