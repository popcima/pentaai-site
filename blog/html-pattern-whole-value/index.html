Write HTML Patterns That Match the Whole Field Value

Use pattern for an explicit input format, with visible guidance and separate required handling. Test full-value matching, invalid patterns and server validation.

By Penta AIPublished 18 November 20262 min read

In this guide

  1. Give the format a visible explanation
  2. Separate missing, mismatched and malformed cases
  3. Match the application’s actual rules

The HTML pattern attribute validates the entire nonempty value of a supported input. It is not a search for a matching fragment somewhere in the string. Begin with the allowed format and a few accepted and rejected examples before writing the expression.

Give the format a visible explanation

<label for="review-code">Review code</label>
<input id="review-code" name="code" type="text"
       pattern="[A-Z]{2}[0-9]{4}" required
       aria-describedby="review-code-help">
<p id="review-code-help">Two uppercase letters followed by four digits, such as AB0123.</p>

AB0123 matches this illustrative format. xAB0123y does not, because matching covers the whole value. An empty value fails the separate required rule. Do not wrap the pattern in JavaScript slash delimiters, and do not rely on a title-only tooltip to communicate the format.

Reference: MDN pattern attribute.

Separate missing, mismatched and malformed cases

Inspect validity.patternMismatch for a nonempty mismatch and validity.valueMissing for an empty required field. If a malformed expression causes the pattern constraint to be ignored, an apparently accepted value is not evidence that the expression works. Keep representative rejected fixtures in the review.

Modern HTML patterns use Unicode-aware v-mode semantics, including specific escaping rules within character classes. Copying a regular expression from another runtime can change its meaning or make it invalid. Prefer a simple expression for a simple rule, and check the documentation when the format includes punctuation or Unicode sets.

Match the application’s actual rules

  • Test the shortest and longest permitted values.
  • Try leading and trailing whitespace.
  • Include lowercase and non-ASCII input in the review.
  • Confirm pasted values receive the same feedback as typed values.

This sample intentionally accepts only ASCII uppercase letters and digits; it would be inappropriate for a person’s name. Do not impose a convenient regular expression on content whose legitimate forms are broader than the design sample. Decide whether normalization occurs, show the result clearly and enforce the same contract on the server.

If the rule depends on another field or asynchronous data, use the custom validity workflow with a useful correction message. Native pattern matching is one local format check, not a complete data-validation system.
