Style List Bullets with ::marker

Adjust native list bullets and numbers without rebuilding them as decorative elements. Understand marker property limits and keep list meaning intact.

By Penta AIPublished 14 November 20262 min read

In this guide

  1. Start with a real list
  2. Recognize the marker box’s limits
  3. Review wrapping, nesting and fallback

Use ::marker to style the bullet or number generated for a list item. It lets a list keep its native marker while you adjust supported properties such as color and font styling. It is not a general-purpose box that accepts every layout or background property.

Start with a real list

<ol class="review-steps">
  <li>Choose a representative page.</li>
  <li>Inspect the computed values.</li>
  <li>Record the implementation decision.</li>
</ol>
.review-steps { padding-inline-start: 1.75rem; }
.review-steps li { padding-inline-start: .25rem; }
.review-steps li::marker {
  color: #174fa0;
  font-weight: 700;
}

This example preserves the ordered sequence while emphasizing its numbers. The list padding controls room for outside markers, and the list-item padding adds a small gap before the text. Tune those values using a multi-line item, not only three short labels.

Reference: MDN ::marker and its supported properties.

Recognize the marker box’s limits

If padding, border or background on ::marker appears to be ignored, inspect whether the property is supported for markers before increasing specificity. Changing the marker’s content is possible in supported implementations, but replacing every ordered number with the same symbol discards the visible sequence.

A heavily designed step badge may need an explicit layout rather than more marker styling. Keep an ordered list when order matters, and avoid maintaining two independently edited sets of numbers. For a checklist with real completion state, use controls and labels; a colored bullet alone does not communicate whether an item is checked.

Review wrapping, nesting and fallback

  • Include a two-line item and confirm the continuation aligns with the text.
  • Try double-digit item numbers without clipping the marker.
  • Check nested lists and a right-to-left layout.
  • Verify the list is still understandable if decorative styling is unsupported.
  • Inspect the accessibility tree and listen to the list structure with a screen reader.

Avoid removing native markers globally just to fix one component. That can alter how other lists look and, in some browser and assistive-technology combinations, how they are exposed. Keep the scope narrow and test the actual structure.

Use logical padding so the indentation follows writing direction. The goal is a readable sequence whose decorative treatment can change without making the content depend on CSS-generated meaning.
