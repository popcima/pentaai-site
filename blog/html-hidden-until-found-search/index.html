Keep Collapsed Content Discoverable with hidden="until-found"

Review hidden-until-found behavior for browser search and fragment navigation. Synchronize disclosure state and provide a usable path when support differs.

By Penta AIPublished 16 November 20262 min read

In this guide

  1. Try a small discovery fixture
  2. Keep application state consistent with browser discovery
  3. Choose an honest fallback

Hidden="until-found" is intended for content that starts collapsed but can be revealed by browser find-in-page or fragment navigation. It differs from an ordinary hidden element, whose content is not presented that way. Treat it as a behavior to test across your supported browsers, not a drop-in replacement for every disclosure.

Try a small discovery fixture

<p><a href="#export-notes">Jump to export notes</a></p>
<section id="export-notes" hidden="until-found">
  <h2>Export notes</h2>
  <p>The sample includes spacing annotations.</p>
</section>

This fixture isolates discovery behavior. In a supporting browser, search for “spacing annotations” and follow the fragment link separately. Before revealing the matching subtree, the browser can dispatch beforematch, remove hidden and scroll to the content. It is not the same as an application calling a generic show function.

Reference: MDN hidden attribute and hidden-until-found states.

Keep application state consistent with browser discovery

If your component also has a disclosure button, its expanded state must agree with content revealed by search. A beforematch handler can help coordinate that path, but the component still needs its ordinary click and keyboard behavior. Test the result instead of assuming a framework’s closed-state render will not hide the content again.

The until-found state can retain a layout box, including visible padding or borders. A blank framed region may therefore be a consequence of the layout rather than a failed search. Styles such as display: none can also interfere with discoverability; inspect computed styles when the fragment does not reveal the section.

Choose an honest fallback

  • Search for text inside the collapsed content.
  • Navigate directly to its fragment from a fresh page load.
  • Verify the visible trigger’s expanded state after discovery.
  • Check space and borders before the section is revealed.
  • Test a browser without the intended behavior and keep another usable route.

Do not place essential instructions behind an unsupported discovery mechanism. When you need a straightforward, broadly usable disclosure, start with details and summary and review its search behavior separately. Document whether your component is an enhancement, what the fallback shows and how browser-driven reveal integrates with application state.
