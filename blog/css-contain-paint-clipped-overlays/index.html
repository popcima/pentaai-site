When contain: paint Clips a Menu or Tooltip

Inspect CSS containment when a descendant overlay disappears at a component edge. Separate paint boundaries, containing blocks and size containment before optimizing.

By Penta AIPublished 15 November 20262 min read

In this guide

  1. Reproduce the boundary without the full application
  2. Distinguish the containment modes
  3. Review the component’s full contract

If a dropdown or tooltip stops at a card’s edge after a rendering optimization, inspect contain on its ancestors. Paint containment constrains descendant painting, so increasing the overlay’s z-index does not necessarily let it escape. First confirm whether the component is meant to contain that content at all.

Reproduce the boundary without the full application

.card {
  position: relative;
  contain: paint;
}
.card .menu {
  position: absolute;
  inset-block-start: 100%;
  inset-inline-start: 0;
  z-index: 100;
}

This deliberately problematic fixture places a menu beyond a paint-contained card. Toggle containment while holding the menu position constant. If the missing portion returns, the boundary is evidence to investigate; a larger z-index is not the first repair.

Reference: MDN contain property reference.

Distinguish the containment modes

Paint, layout and size containment have different consequences. Paint and layout containment can also establish containing-block and stacking behavior. Size containment allows sizing calculations to ignore descendants, so adding it to an auto-sized component can change its dimensions dramatically.

The content shorthand combines layout, paint and style containment, while strict also includes size containment. Treat those as bundles of behavior, not generic “make it faster” switches. Inspect the computed value and the component’s actual layout needs before using a shorthand.

A legitimate repair may remove unnecessary containment, put the overlay outside the contained subtree or use an appropriate top-layer pattern. Moving an overlay introduces positioning and focus responsibilities of its own, so choose a component-level design rather than a one-line escape trick.

Review the component’s full contract

  • Open menus and help panels near every edge.
  • Check focus outlines and other descendant paint near the boundary.
  • Inspect absolute and fixed descendants after the change.
  • Test short and long content when size containment is involved.
  • Measure any performance benefit before keeping the optimization.

Containment does not create a separate CSS selector scope like Shadow DOM. Keep styling encapsulation and rendering isolation conceptually separate. Use the containing-block guide when a positioned child moves, and the stacking guide when it layers incorrectly. Those symptoms can accompany clipping but require their own diagnosis.
